# Prefill 的分核与访存算例

以下数字是 950DT 资源模型的设备时间。算子合同来自三个模型的 rank 0 系统捕获。新增 prefill 融合实现及带行距的组合窗均缺同实现 DT/PR CA 校准，误差记 N/A。输入长度单位为 token，带宽按十进制 GB/s。

## Flash 候选索引器

单卡 B=8，每个请求当前 Q=4096，读到 L=32768；每个查询有 H=32 个 BF16 头，每头 D=128。输入块号有 2048 个槽，每块 8 个 key，每行输出 512 个位置。模型遵循捕获的全表打分合同。BF16 点积一共有 B×Q×L 个 query-key 对，每对 2HD 次运算。因果和块掩码作用在打分之后，因此不会减少这部分计算。光按 512 个最终位置收费会少算 64 倍。

每个 AIC 领同一请求内的 4 个 query，键按 128 个一页流入；尾部不足 4 个 query 时取实际行数，再按 MMAD 的 M 对齐。共有 8192 组；32 AIC、64 AIV 时有 256 波。每组的中间页取读、MMAD、逐头加权归约发起间隔的最大值，再为最后一页、排序、位置映射和写出收尾。按核心领取的整组和尾组数取最晚完成者，同时检查跨核共享 HBM/L2 服务时间。分核采用周期计数，查询时间无需随 Q 展开所有行。冷启动块 L=Q 时，前 511 行可见位置不足 512，输出仍写满 512 槽并计入填充。B=8 时共有 1,046,528 个填充槽。在内置 DT 配置下，此例设备时间 **26.961 ms**，把 L 加至 1,048,576 后为 **839.853 ms**。同一形状在系统芯片资源覆盖配置下会重新定价。[每页服务及排序参数的推导](candidate-filtered-indexer.md) · [实现](../../src/operator_model/operators/attention/candidate_indexer.py)

## Kimi K3.1 Pro 的 64-token Chunk KDA

以 BF16 输出 [1,2048,12,128] 为例。每个请求的序列切成最多 64 token 的块。用 H 表示本卡头数，K 和 V 表示键和值的逻辑通道；此例 H=12、K=V=128。Q/K/V 的底层存储是 packed MXFP4，每 32 元素一组 E8M0 scale，状态张量的接口是 FP32。三阶段设计按块独立准备、中间有序更新状态、最后并行产出结果。假设两个点积用原生 4 位，状态矩阵乘的输入转换为 BF16、累加保留 FP32，中间结果可以片上交接。片外临时张量和额外启动会增加实际时间。

设 n 为各请求中每个块的实际长度，求和覆盖全部块，R=H×Σn、S=H×Σn²、J=H×Σn³、G=H×块数。各阶段按以下工作量定价。

| 阶段 | 运算量 | 依据 |
|---|---|---|
| 块准备 | MXFP4 Cube 为 2KS；BF16 Cube 为 2(K+V)S；FP32 Vector 等价工作为 R(10K+3V)+⌊J/3⌋ | 两个三角点积合成整块工作，形成 W/Y 两个投影，再付出门控与三角求解的向量工作。Vector 系数是运算代理。 |
| 状态更新 | BF16 Cube 为 4RKV；FP32 Vector 为 RV+2GKV | 两次状态矩阵积，逐块融合状态。不同请求、头、V 条带可并行，同一条状态链按块顺序执行。 |
| 输出 | BF16 Cube 为 2RKV+2VS | 从先前状态投影并合并当前块的块内注意力。 |

p 位操作执行 F 次、分配 a 个 AIC 时，时间为 F/(10⁶ × Pₚ × a/A)，单位 µs。Pₚ 是整片对应精度的 TOP/s，A 是芯片总 AIC 数；Vector 同理。准备阶段先累加同引擎不同精度需求，再和 Vector 需求取较大值。状态阶段以 UB 可容纳的 V 条带数限制活动链，并按最长链修正不等长请求的负载。三阶段串联，张量读写在可重叠范围内并行。一次 2048-token 调用包含 32 块、384 个头块任务，初始与最终状态各 786,432 B。DT 预测 **18.865 µs**。三个阶段各有 4587 cycles 的启动代理，借用 950 索引器校准参数 first_issue_cycles 的数量级；该代理和 BF16 状态路径均未经 MXFP4 整窗验证。[排程与参数](../../src/operator_model/system_routes/prefill.py) · [BF16 KDA 样例](kda_chunk.md)

## 同一 Kimi 调用图的 Vector 算子

下表沿用单请求 2048-token 的捕获。分块后取最忙 AIV 的读、计算、写回服务。首块串联，后续块取可重叠资源中的最大服务时间；全片读取和写回共同受 HBM 带宽约束。流式和反量化类启动代理分别取自 Add 和 AntiQuantV2 的归档小窗。[Vector 时间公式与启动参数](system-vector-routes.md)

| 节点 | 分块和计费示例 | DT 预测 |
|---|---|---:|
| 因果深度卷积与 SiLU | BF16 [2048,4608]、4 抽头。通道块最多 256，时间块最多 64，并按 UB 下调。相邻块额外读 3 行 halo，初始状态只在已有历史时读。末态写 3×4608 个 BF16。算术按每元素 2×4+4 个等价操作。 | 首块 12.355 µs；续块 12.362 µs |
| L2Norm | [1,2048,12,128] 按 24,576 个 128 元素的行归约；每行按 3D+2 个 FP32 等价操作计平方、求和、倒根和缩放，BF16 输入、输出各读写一次。 | 5.812 µs |
| 写入索引缓存 | 每个新 key 是 BF16[128]。先做带 FP32 权重和偏置的 LayerNorm，再按 32 元素一组打包 MXFP4。每行写 64 B 值和 4 B scale，本次共写 **139,264 B**。按位置散写，整张预留缓存的容量不进入写量。 | 3.031 µs |
| zeros_like 状态 | FP32 [1,12,128,128] 分条带写 786,432 B，源输入只提供形状。 | 2.899 µs |
| copy_ 状态 | 同一形状，读 786,432 B 源并写等量目标，覆盖前的目标不计读取。 | 3.060 µs |

## 最后一个 token 的词表投影

Pro 的 prefill 在 B=16、Q=4096 时给词表投影的 BF16 激活是 [16,7168]。行距为 29,360,128 个元素，即一个请求的 4096×7168；每行内部是连续的。这里假设先把 16 行收齐再运行转置权重矩阵乘。收齐阶段读和写各 16×7168×2=229,376 B，再付出 [M,N,K]=[16,16160,7168] 的矩阵乘时间。若调用方直接传入连续的 [16,7168]，这段打包消失。这个例子说明仅传 M、N、K 还不足以确定实现价格。[矩阵乘分块](system-cube-routes.md)
