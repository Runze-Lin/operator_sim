## 真正的 A5 融合 kernel

通过发布包的 `installed_hit` 验证相同的 PA_BBND / cmp_ratio=1 AOT，设备映像 SHA-256 为 `b3a854470fe46368ac752ccccd7ed0bb7ffb087b658373c2ac97bfce027ae4ff`。在 CA 中，AICPU 元数据任务报告 `unsupported task type: AICPU_D`。为计时融合内核，先在主机按发布的 metadata 算法取得并校验 1,024 个 int32 字，再在 CA 中执行原生 AOT、读取输出并检查全部 512 个全局位置。下表的 CA 值包括 kernel 内 gather、Cube、Vector 与所需的跨核归并。主机生成分核表的时间不计入设备窗。

| 每卡 B、Q、逻辑 L | 候选块 / 页表列 | v1.11 历史预测 DT / PR（µs） | 融合 CA DT / PR（µs） | 误差 DT / PR |
|---|---|---:|---:|---:|
| 1、1、1,024 | 81 / 8 | 6.831 / 6.836 | 11.088 / 11.483 | −38.39% / −40.47% |
| 1、1、1,024 | 81 / 8,201 | 8.072 / 8.077 | 11.352 / 11.225 | −28.89% / −28.05% |

两次均为两片独立的 32×512×128 MXFP4 MMAD，对应 648 个有效 key、1,024 个发出的 key 槽；两端均有 2 个发出点积的 AIC、4 个协作 AIV 与跨片归并。只扩大页表、保持数据和候选 ID 相同后，四个活动 AIV 的 `LD_XD_XN` 总数从 15 升到 271，证实切到标量地址路径。相对小表，模型在两端均增约 1.24 µs；CA 改变 +0.264 / −0.258 µs。额外的 256 条 load 可与其他阶段重叠，两次独立进程的差也含启动变动，不能把它直接换算为每块固定等待。[原生 AOT、分核表与逐窗收据](../../calibration/candidate_indexer/fused-qsli.json)

## 1Mi 满候选单行，默认分核

Q=1、L=1,048,576、c=2,048、页表 8,201 列，一行的 32 个 tile 分给多个团队。输入含 256 个有物理映射的候选页，跨度覆盖首尾，输出 512 个全局 ID 在两端均与 CPU 的 MXFP4/E8M0 golden 一致。每端收到 32 条 32×512×128 的 MMAD_MX。DT 32 个物理 AIC 各 1 条；PR 28 个物理 AIC 中 24 个各 1 条、4 个各 2 条。和这两份合格 trace 同次启动的 FIXTURE 日志记录 DT 32 个、PR 28 个 metadata worker。此前另一次 PR 数值检查曾报告 32；该次没有合格 trace。单个工作分片可以包含两个 tile，tile 数与待归并列表数须分开统计。

| 单位 µs | v1.11 | v1.12 | 固定原厂分核表的 CA | 旧误差 → 新误差 |
|---|---:|---:|---:|---:|
| 950DT | 11.390 | 18.107 | 21.630 | −47.34% → −16.29% |
| 950PR | 12.988 | 18.997 | 21.092 | −38.42% → −9.93% |

两端最后退休的都是 core0 的第一个 AIV。按真实指令边界分解，DT/PR 在第一条 MMAD 前用去 **9.979 / 9.498 µs**，从首个发起到最后一个 MMAD 退休为 **1.378 / 2.701 µs**。随后，最后一个局部分片的列表写完分别还要 2,849 / 2,942 周期，等到归并 AIV 发起首读又要 1,488 / 1,203 周期。归并首读到全核最后退休为 **7.645 / 6.381 µs**。这几段相加为对应的完整设备窗。[原始单行收据](../../calibration/candidate_indexer/long-row-results.json) · [同一次运行的源码和 trace 核查](../../calibration/candidate_indexer/v112_merge.md)

旧模型用普通 LI 的首发代理和直方图开销为归并定价。原生 QSLI 同时要发布各分片、读回位置和分数、等待所有前置写入。最终归并 AIV 每轮至多增加七份列表，中间的 top-512 也会写回并在下一轮重新读入。因此 DT 需要五轮，PR 需要四轮。v1.12 调整上述环节后，单行仍分别低估 **3.523 和 2.095 µs**。真实归并输入 DMA 合计 3,496 / 2,920 周期，而模型给出 2,523 / 2,103 周期；首个满核波也比六窗共用的启动和供数预算晚。DT/PR 实测时间比 1.026，v1.11 为 0.877，v1.12 为 0.953，双端快慢方向仍判反。六窗中同时改变了工作量、并发度和页位置，现有证据不能继续分离每个因素对首次供数的影响。[逐轮耗时与差距](../../calibration/candidate_indexer/v112_merge.json) · [算例和对照图](../examples/flash-a5-qsli.md)

下表把时间分到相同的两个里程碑。CA 取全核最早 MMAD 发起和最晚局部分片写退休。模型将首发理解为「启动 + 首次 gather/发布/读」，将最慢团队完成理解为「启动 + 关键团队预算」；后两者是预测的里程碑。每行三段之和就是完整窗，单位 µs。

| 设备与口径 | 首指令 → 首 MMAD | 首 MMAD → 最晚局部分片写完 | 最晚局部写完 → 整窗结束 |
|---|---:|---:|---:|
| DT · v1.11 / v1.12 / CA | 6.961 / 8.474 / 9.979 | 0.666 / 1.812 / 3.104 | 3.764 / 7.820 / 8.547 |
| PR · v1.11 / v1.12 / CA | 6.961 / 8.474 / 9.498 | 2.869 / 4.013 / 4.484 | 3.158 / 6.509 / 7.110 |

原来缺的 10.240 / 8.104 µs 中，最后一段分别占 4.783 / 3.953 µs，约一半。两端实测的首发相差 0.482 µs，新模型共用此项系数。中段实测 PR 比 DT 慢 1.380 µs，模型把这个差估成 2.201 µs；末段实测 DT 又比 PR 慢 1.436 µs。三项抵消后，仍相差约半微秒就会改变整窗快慢顺序。

## 1Mi prefill · 默认分核的 32-query 独立验证

每卡 B=1、Q=32、L=1,048,576。每行收到 2,048 个候选块。32 行共享块 ID，行内用各自的 query 和因果边界打分，16,384 个输出位置全部通过 CPU 校验。DT 上原厂 metadata 将 32 个整行分别交给 32 个 AIC、64 个协作 AIV，不需跨核合并一行。trace 显示每 AIC 32 条 32×512×128 的 MMAD_MX，共 1,024 条；按各条 MMAD 的发起到退休统计，同时有指令在途的 AIC 峰值为 20。

| 验证项（设备时间，µs） | 原资源先验 | 单团队标定后冻结 | 原生 CA | 当前误差 | 冷 U | 970DT 外推 |
|---|---:|---:|---:|---:|---:|---:|
| 950DT，v1.11 独立单波，v1.12 同集回放 | 52.021 | 75.856 | 84.792 | −10.54% | 11.88% | 46.689 |

原先验低估 38.65%。间隔模型在看这次并发结果前已经冻结。首个 MMAD 在 19,732 cycles 发起，最后一个在 133,760 cycles 退休，最后完成的是 core9 的第一个 AIV，整窗 139,907 cycles。并发下的启动、各团队的供数进度和 AIV 的收尾都会进入整窗，当前一例不能将剩余 8.937 µs 分摊给单一资源。离线采集与导出 758.1 s。PR 的新留出使用相同张量，结果见下表。这个独立单波给 4,096 行外推提供了核对点。它使用离散选页和有限物理 backing，同波各行共享候选，无实测的跨波冷热页分布。[冻结预测](../../calibration/candidate_indexer/qsli-interval-wave-prediction.json) · [完整 CA 收据](../../calibration/candidate_indexer/prefill-wave.json)

### 950DT · 候选页随行变化的两波独立留出

Q=64，B=1，逻辑历史 1Mi，保留每行 256 页、2,048 块和 top-512，给全部 8,192 个有效逻辑页分配不同的物理页。相邻行的集合交集固定为 208 页，每行的候选读取顺序也不同。原厂调度把连续两行交给同一团队，32 个团队各做 64 个 tile，无跨团队归并。64 行共选到 2,176 个物理页。逐团队核对地址多重集，计得实际 gather 描述符对应 71,303,168 B，其中不重复的折叠源记录为 9,469,952 B。前者为 GM 读取请求，后者为唯一地址覆盖，两者都不能直接当成物理 HBM 流量。

## 普通 MXFP4 score + top-512 子阶段

每组 B=1、H=32、D=128，FP4 E2M1 Q/K、两侧 E8M0、非均匀 FP32 权重。先由 GatherV2 收集指定 81 个不连续八位置块的 payload、scale 和原位置。普通库接口 `aclnnQuantLightningIndexerV2` 只见到 648 个紧凑 key，之后在设备上重映射并排序。本实验显式使用一片 Cube 打分，Q=4 时四行共享同一套块。原生 A5 QSLI 可以按 query 收不同块，并按 metadata 跨核拆行。

| Q | 源表 L | 普通 QLI 冻结预测 DT / PR（µs） | 普通 QLI 完整 CA DT / PR（µs） | 单窗偏差 DT / PR | 六个串行 kernel 的设备窗之和 DT / PR（µs） | 每 SKU 正确输出位置 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 1,024 | 8.987 / 7.698 | 11.249 / 10.588 | −20.1% / −27.3% | 24.102 / 23.132 | 512 / 512 |
| 1 | 2,056 | 8.987 / 7.698 | 5.600 / 5.605 | +60.5% / +37.3% | 14.237 / 14.290 | 512 / 512 |
| 4 | 2,056 | 11.785 / 10.042 | 6.875 / 6.804 | +71.4% / +47.6% | 16.380 / 16.415 | 2,048 / 2,048 |

每个普通 QLI 窗都发出 **6 条 MMAD_MX**，五条 N=128、一条尾部 N=8；Q=1 时指令 M=64，Q=4 时 M=128。AIV trace 中同时有 RV_VMULA 等打分后处理指令。每个 SKU 均有 3,072 个输出位置通过有序 golden，候选之外放置的高分干扰项未被选中。两组 Q=1 保持相同紧凑表大小，首个设备窗却约是后一个的两倍。源表长度、进程内调用次序在这个实验中一起改变，两个窗不能估计长度的时间斜率。一次独立验证覆盖 3 个几何，普通子阶段代理 WAPE 为 **44.51% / 35.75%**，最大误差 **71.42% / 47.59%**。这说明相邻实现的绝对时间仍有显著不确定性。

普通 kernel 为 ops-transformer 安装件 `QuantLightningIndexerV2_fdc74cd4e721a142565ce75cd1744026.o`。上述 36 个设备窗均从真实 per-core trace 得出。两端各自日志跨度 176 / 177 s。逐 kernel ELF、hash、MMAD 个数、核和首发/退休周期见[CA 收据](../../calibration/candidate_indexer/mx-controls.json)与[冻结的子阶段预测](../../calibration/candidate_indexer/mx-controls-freeze.json)。

## 1Mi 外推与部署边界

1Mi/B1 的最后一个 prefill 块有四个相同形状的候选消费节点。历史后端为每层报价 3,665.040 ms；BF16 全表 Cube 方案为 106.858 ms；宽表固定间隔先验为 6.211 ms，按单团队实测的 31 段平均间隔校准后为 9.262 ms。取预留 8,201 列页表、每记录 64 个标量寻址周期。在同一张图把这个参数改为 0 / 256，在显式固定间隔假设下，单层为 1.650 / 21.463 ms，全块为 450.102 / 529.354 ms。这是单参数敏感性，尚未包含 AICPU metadata、索引整理、缓存维护或其他未捕获的真实部署差值。当前没有 1Mi 整块或线上 1Mi 计时真值。950PR 的 Q32 CA 已验证同址共享情况下的 GM 读与设备整窗；大批次稀疏 gather 的物理片外带宽仍未知，970DT 计时均为移植情景。[同图微秒记录](../../calibration/candidate_indexer/context-sensitivity-scalar.csv)

保持末块原图其余节点相同，从两种实测页分布分别外推。重复 DT 的 32-query 共享页样本 128 次，按启动处理方式得到 0.484277 / 0.486915 s；重复 64-query 不同页样本 64 次得到 **0.462707 / 0.464015 s**。两种 64 行情景的候选层单次为 4.801 / 5.128 ms，均明显小于系统资源模型的 9.262 ms。四个消费层之外的关键路径约 443.501 ms，因此整块的相对变化小于算子自身差异。0.480550 s 仍可作该图的粗估；单窗覆盖与误差不足以认证这个数为部署精度。四个情景不构成统计置信区间。线上候选页相关性、冷暖缓存、AICPU 和上游准备仍缺实测。[同图替换四个节点的逐项结果](../../calibration/candidate_indexer/v112_context_multiwave.csv) · [33 组请求](../context-sweep.md)
