# 算子建模方法

给定一次实际调度交给单卡的张量，operator-sim 估计安装库算子的**设备执行时间**。先从算法得到有用运算与张量字节，再按库实现选择分块和分核。目标芯片配置决定各阶段的计算和搬运能力，数据依赖决定它们能否重叠。950DT 和 950PR 的 CA 提供阶段观测与计时参照。预测新芯片只读取部署方提供的配置，假设相同的实现族仍可用。将来如果库改变布局、精度、核内算法或分核策略，应替换实现模型，保留算法工作量和系统调用接口。

输入包括算子、单卡 shape、dtype、必要的布局与属性、目标芯片。有状态的调用还可传前序信息。输出包括设备微秒、预计参加工作的 AIC/AIV、分精度 Cube/Vector 有用计算量、逻辑读写字节，以及该实现可解释的分块和阶段耗时。返回的状态和资格说明属于结果的一部分。在线常驻进程查询目标为 100 ms 以内，离线 CA、首次导入和 Python 进程启动单独计时。[工具入口](../README.md) · [逐算子误差和校准状态](error-analysis.md)

AIC 指 Cube 计算核，AIV 指 Vector 计算核。下文用 MTE2 表示从全局内存读入 L1 或 UB，MTE1 表示从 L1 向 L0 装载，MTE3 表示从 UB 搬出，常见用途包括向全局内存写回，也包括 A8W4 将展开后的权重交接到 L1。MMAD 执行矩阵乘累加，FIXP 负责输出转换与写出。这里的 GM（全局内存）请求可能命中 L2。

## 公式中的数怎样得到

读一个阶段先问两件事。一是**这次调用要做多少工作**，例如从本核的 tile 算出要读多少字节。二是**完成单位工作要多久**。这两个量可以来自不同地方。以下用 FA 的 950PR 算例说明怎样从 950DT 开发数据得到可迁移的参数。

| 数值的来源 | 怎么得到 | 换芯片时怎么用 |
|---|---|---|
| 张量与实现 | 一张 256×64 的 BF16 K 页占 32768 B，V 页同样大。所以一次 K/V 服务的分子为 65536 B。页深和一核分到的行数由所选库路线决定。 | 按目标核数、片上容量与实现重算分块和工作量。 |
| 芯片规格 | PR 的 BF16 Cube 峰值 378 TOP/s，28 个 AIC，1.65 GHz，故每核每 cycle 可做 `378×1000/(28×1.65) = 8181.818` 个标量操作。 | 直接代入目标配置。这里的频率用于从峰值换算为每 cycle 吞吐。 |
| CA 中直接量到的节拍 | DT 的 [9,32768,64,1,1] 有 128 页。K/V 的 112 个中段发起点分别拟合出 853.22983、853.40471 cycles/页。两条流都要推进，取较慢者。 | 同一内核、相同双缓冲与同步策略下先继承 cycles。若目标的读、算或其他服务更慢，页间隔随最慢约束改变。 |
| 扣除已解释工作的残差 | 同一路线的 QK，两条 MMAD 从首发到末次退休为 211 cycles。扣除补齐后运算的理想服务 64.0796，再除以两片，得 73.4602 cycles/片。 | 理想服务按目标 Cube 吞吐重算。残差可能含发起、等待和流水填充，迁移这一项需要相同实现的假设。 |
| 等价工作或经验假设 | 页内向量工作约定为 `5×r×n + 3×r×d`。固定了 5 和 3，才可用工作量除以核上 SIMD 忙时得到有效速率。单个窗无法同时识别权重和绝对速率。 | 使用相同的工作单位和算子路径。按每核 Vector 峰值迁移其有效速率，970DT 的结果列为外推。 |

算子的结构决定哪种观测能回答问题。BF16 Matmul 的首读既有固定响应也有按字节增长的服务，因此取 17 个开发窗，以关键核首对读的载荷为横轴、两条都退休的时间为纵轴，拟合截距和斜率。首响应为 1173.46 cycles，斜率倒数为 47.148 B/cycle。GMM2 的核上有多个引擎同时活动，模型保留这些引擎**同时活跃了多少 cycles**，重叠区间只收一次费用。两者的有效价格都有明确的观测对象，迁移时也各有适用条件。[Matmul 的 17 窗观测及回归](examples/matmul.md#从-17-个开发窗复算-bf16-参数) · [GMM2 的并发区间怎样量](examples/gmm2.md#如何从真实-gmm2-指令得到模板系数)

本文件与算例用 `⌈x⌉`、`⌊x⌋` 表示向上、向下取整，`sum` 表示求和，`median` 表示中位数。资源排程通常先算目标芯片的 cycles，再按 `设备时间(µs) = 总 cycles / (1000 × 目标主频 GHz)` 换算。例如 950PR 每 µs 有 1650 cycles，970DT 每 µs 有 1800 cycles。CA 原始字段中的 tick 对应所用设备时钟的 1 cycle。GMM2 的参考并发区间和 Recurrent KDA 的阶段拟合可以直接使用 µs。对调用方，`latency_us` 和提供的 `stages_us` 统一使用 µs。[模板算例](examples/gmm2.md) · [阶段拟合算例](examples/kda_recurrent.md)

要复算 FA 的所有价格，可运行 `python3 calibration/examples/replay_fa.py`。程序先从开发窗的整数时刻、区间并集和芯片配置计算参数，再与发布参数比较。其他算例在各自的阶段分解旁交代开发 shape、观测边界、统计方法和可辨识范围。完整 CA 整窗用于核对端到端误差；仅靠这个总数，无法恢复各条并发流水的价格。[FA 的取样、数字与复算入口](examples/fa.md#这些速率和固定开销从哪里来) · [各算子的算例索引](#如何复算例页里的微秒数) · [完整窗的误差口径](error-analysis.md)

## 三种流水怎样建

### Vector · 从一次 UB 能装多少数据开始

1. 识别可独立的工作单元。MX 量化可按行和 32 元素的组切分。RMSNorm 的一个结果依赖整行归约。mHC Post 可以沿 token 或通道分配任务。决定单元后，先算最忙物理核分到多少行、多少列，以及最后一块的实际长度。
2. 计算统一缓冲区（UB）能同时容纳的输入、输出、临时值和双缓冲槽。对每块分别建立读入 MTE2、向量执行、写回 MTE3。有归约时加数据依赖，有两个输出时分开安排收尾。
3. 对第一块支付启动和首读响应，对中间块按可持续**发起间隔**推进，对尾块按剩余元素付费。若所有核合计的片外字节超过共享带宽能提供的服务，还需等待共享端口。以实际最晚退休的核心为参照校准。

例如 [8192,5120] 的 RMSNorm 在 950DT 上每核负责 128 行，完整行块最多 5 行，最忙核要做 26 块。下一块输入可以在上一块写回时发起，同一行的归一化则必须等平方和与倒数根。把所有读写描述符的持续时间直接相加会把在途等待重复计入。[RMSNorm 逐步算例](examples/rmsnorm.md)

#### 双发射怎样进入 Vector 的耗时

950 的寄存器 SIMD 支持双发射。按当前 FP16 乘加峰值的口径，`128 MAC/条 × 2 条/cycle × 2 ops/MAC = 512 ops/cycle/AIV`，折算为 950DT 全片约 54.07 TFLOP/s，配置取整为 54。对任意已含双发射的峰值，用 `1000 × 全片峰值(TOP/s) / (AIV 总数 × 主频 GHz)` 就得到每核每 cycle 的参考吞吐。

两条指令能否配对发射取决于指令类型、执行资源和操作数是否就绪。举例，8 条可配对且独立的指令最少用 4 个发射 cycles。8 条只能单发射的指令至少用 8 个发射 cycles，依赖还可能让间隔更长。DynamicMXQuant 的组最大值和 scale 有前后依赖，RMSNorm 的归一化要等行归约完成。算子、tile 和尾块可以有不同配对比例，也可能全程单发射。

当前模型从 CA 的阶段时刻校准**有效循环成本**。量化用每循环等效工作量与目标参考峰值计算 SIMD 服务，RMSNorm 用归约组的阶段价格与 FP32 每核吞吐比调整。两条路线在实测价格里吸收了实际发射与等待。若要单独量双发射，需要同一 AIV 上有逐指令发起时刻和指令类别的 trace。970DT 暂用 950 的每核 Vector 能力假设。总峰值变化只能改变参考吞吐，指令配对、归约或转换速率变化需要对应的阶段证据。[950 SIMD 架构，白皮书 §4.1.2](https://public-download.obs.cn-east-2.myhuaweicloud.com/ascend/%E6%98%87%E8%85%BE950%20NPU%E6%9E%B6%E6%9E%84%E7%99%BD%E7%9A%AE%E4%B9%A6.pdf) · [量化循环算例](examples/quant.md#向量循环怎样用峰值与-ca-定价) · [RMSNorm 归约与写回](examples/rmsnorm.md#计算怎样掩盖写回)

### Cube · 按输出矩形和 K 页安排乘加

1. 对稠密矩阵乘，输出块由 M、N 两轴给出。块数少而 K 很长时，库可能沿 K 分段并将部分和交给 AIV。对窄 B 且 M 很长的投影，权重可驻留 L1。分支决定活动核、尾波与额外工作区。
2. 每核把 K 切成能放入 L1 的页，再拆为 L0 片段。为每页记录 GM→L1、L1→L0、MMAD 和最终 FIXP 的工作量。Cube 的峰值作用在实际填充后的乘加量。有效 FLOP 单独返回给系统。
3. 两个缓冲槽允许下一页预读。共享 Cube 的乘加串行，写描述符可提前提交、等累加完成后退休。只在依赖或资源把后继推迟时增加临界路径。长序列将相同波次按组推进，完整计入第一波、尾波和缓存过渡。

例如 [1280,2048,512] 在 950DT 上有 40 个 256×256 母块，首波 32 个整块，余下 8 个分别拆成四个 128×128 子块。32 个 AIC 各做两块，每块两页 K。模型时间 12.449 µs，CA 全核时间 12.219 µs。页级排程与末核的逐指令图共用设备零点。[Matmul 两波两页算例](examples/matmul.md)

这里的 **输出 tile** 是沿 M、N 切出的输出矩形，**L1 K 页**是同一矩形沿 K 切出、一次预读到 L1 的 A/B 数据，**L0 MMAD 片**是一条 MMAD 实际消费的 K 段。例如同一 shape 在 970DT 上，输出 tile 为 144×160，一个 tile 需要两个 K=256 的页，每页拆成 4 条 K=64 的 MMAD。FA 的 KV 页沿 KV 序列切分，Vector 的 UB tile 则是一次在 UB 处理的行块或列块。[Matmul 三层分块与 970DT 外推](examples/matmul.md#同一-shape-外推到-970dt)

### Cube + Vector · 把交接和并发写进依赖图

1. 给每种任务同时标明数据生产者、消费者和执行资源。FA 的 QK、PV 争用同一 Cube。softmax 运行在 Vector。下一页读、上一页 PV 与当前页的向量处理可能并行。依赖关系决定首轮和末轮由谁收尾。
2. 已能识别算法阶段的实现直接定价和排程。仅有参考 trace 的实现保留不同核类型上资源同时工作的区间，用该区间中增长最多的资源需求伸缩其时间。模板法对未见分核和新芯片的预测更依赖“重叠关系不变”的假设。
3. 多个实际 kernel 串行调用时分别计算设备窗再求和。系统层另外安排 host 间隔、排队和通信。一个融合 API 和它的拆分组合属于不同调用合同，只应选部署实际采用的一条。

例如 FA 用 [Q=9,KV=131072,D=64,B=1,H=1] 时只有一个 query 任务。增加全片 AIC 数不产生更多 query 并行。512 页 KV 中，每页 QK 和 PV 各有两条 MMAD。当前 950DT 长循环主要受页发起控制约束，不能把所有 FA 都归为 Vector bound。[FA 长 KV 算例](examples/fa.md)

### 精度如何改变分块、计算和输出

系统需要分别指定 A、W、scale、累加器和 Y 的精度。选择库路径后才确定 tile，以及负责解包、乘加、归约和写回的硬件。设页中有 `u` 个元素，存储位数为 `b`，紧密打包至少占 `⌈ub/8⌉` B；实际占用还包括每行对齐、scale、临时展开结果和多缓冲。各缓冲中的字节数都必须小于对应容量。例如同一页的 FP4 权重搬入占半字节/值，若 AIV 将其展开成 FP8，交给 Cube 的这份数据占一字节/值。两份在 UB 中的同时存活时间会改变可选 K 页深。MXFP4 E2M1 和 MXFP8 使用每 32 个值一份 E8M0 尺度；块格式来自规范，页调度由内核实现选择。换输出精度也可能改变 FIXP 或 AIV 的工作，因而触发另一条库路径。[OCP MX 规范，表 1](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf)

| 950 上实际建模的调用 | 片内工作与输出 | 系统应如何计时 |
|---|---|---|
| 稠密 A4W4 → BF16 | Cube 直接发射带 E8M0 尺度的 FP4×FP4 MMAD，累加后写 BF16。 | 一次 V3 设备窗。按 4-bit 峰值计算 Cube 工作，按打包字节计算搬入。 |
| 稠密 A8W4 → BF16 | AIV 按页将 FP4 权重展开为 FP8，交接到 L1；Cube 发射 FP8×FP8 MMAD。两侧 scale 参与乘加。 | 一次 V4 设备窗，含片上展开和交接。参数 `weight_dtype="mxfp4"` 选择该实现。 |
| 上述 BF16 结果再单独量化到 MXFP8 | 后继 DynamicMXQuant 逐组求幅值、形成 E8M0 scale、转换及打包输出，写数据和 scale 两个张量。 | 若图中确有两个串行 kernel，用两次 `estimate` 的设备窗之和。中间 BF16 的逻辑写与读分开计，实际 HBM 流量取决于 L2。 |
| 已校准的 GMM1–SwiGLU–MXQuant | 从 gate/up 的累积结果计算 SwiGLU，核内按组量化激活，将 MXFP8 和 scale 一起交给 GMM2。 | 选择对应的融合模型；其设备窗已经包含输出量化。 |

输出量化是否要找最大值，取决于 scale 来源。动态 block32 需对每个组的有效值求最大幅值，生成尺度，再缩放转换。若调用方给定静态尺度，工作是读取尺度并按其广播、缩放和转换。仅输出到 BF16 的数值舍入也和动态 MX 量化具有不同依赖。目前稠密两路接受 BF16 输出，要求它们直接融合输出 MXFP4/MXFP8 时返回 `unsupported`。只有匹配 dtype、分组轴、scale 格式和布局的独立量化才可拼接。

例如 950DT A8W4 的 [9,128,256] 输出 BF16，若下游要求独立的 block32 E4M3FN 转换，`estimate("matmul",(9,128,256),{"weight_dtype":"mxfp4"},dtype="mxfp8")` 给 3.946 µs，`estimate("quant",(9,128),dtype="bf16")` 给 5.159 µs，两个串行设备窗合计 9.104 µs（使用未舍入数）。前者写 `2×9×128=2304` B；后者读回 2304 B，写 `9×128=1152` B 有效值及 `9×(128/32)=36` B scale。这里是两次模型调用的组合，完整组合没有单独的 CA 误差。若部署使用融合输出，应按融合内核验证与计价。[支持的精度合同](precision-coverage.md) · [A4W4/A8W4 输入与流水](examples/mxfp4-design.md) · [融合输出量化](examples/grouped_matmul_swiglu_quant_v2.md)

## 怎样用目标芯片定价

设备延迟用 µs 表示，工作时钟用 cycle / cycles 表示，容量和流量用 B 表示。十进制 GB/s 对应 1000 B/µs。KiB、MiB 分别表示 1024 B、1024² B。乘法与加法各算一次操作，FMA 算两次。

| 量 | 计价方法与来源 |
|---|---|
| 芯片峰值 | 设峰值为 P TOP/s、对应类型有 C 个核、频率 f GHz。每核每 cycle 能力 p=1000P/(Cf)，单位 ops/cycle。若每核每 cycle 有 m 个乘加，峰值为 C×m×2×f/1000 TOP/s。m 包含可用的双发射次数，公式中的 2 用于乘加计数。实际参与算术的指令类型决定选择哪一条峰值。 |
| 有效计算工作 | 有用工作来自数学定义。实际片段工作按 kernel 的对齐、padding、尾块和指令粒度计算。阶段成本可写为 a+n·j+F/p 个 cycles。a 为一次启动等待，n 为发起次数，j 为每次额外发起成本，F 为该阶段实际算术工作。不同阶段中控制已由实测响应计入时不重复添加。 |
| 单核读写 | 对 b B 的请求，响应近似 L+b/r。L 是首响应或固定路径延迟，r 是目标端口的有效 B/cycle。响应时间涵盖在途等待，第二次发起时间受发起间隔、缓冲槽和带宽约束。MTE2 读和 MTE3 写的本地上限分别定价。 |
| 芯片共享流量 | 设活动核数为 A、每核持续发起能力为 r、共享链路带宽为 B。有效总字节率上限为 min(A·r·1000f,1000B) B/µs。读写比例、缓存重用、并发窗口会进一步降低实际服务率。逻辑张量字节、实际 DMA 字节与片外控制器字节分别记录。 |
| 依赖调度 | 事件开始 s=max(前驱退休、同资源下一次可发起、缓冲槽可复用)，退休 e=s+阶段响应。全窗从全片首发到最后退休。稳定的 J 次循环常写成首轮+ (J−1)×II +排空。II 是瓶颈资源或依赖链的每轮发起间隔。尾块的长度按实际形状重算。 |
| 前序状态 | resident_aiv 是同一调度上下文中可见的前序 AIV 状态。首次、扩核与热态可能得到不同时间。仅传 shape 时，某些路线对模型的最短、最长状态 l、h 给出 2lh/(l+h) 的点估计，在两个端点平衡相对误差。该值没有隐含的冷热发生概率。 |
| 参考模板 | 对参考例 r、核类型 h、同时活跃资源集合 A，记录原区间时长 d。对目标例的区间贡献为 d×max(q∈A 的资源需求倍率)。倍率同时考虑工作量和目标服务能力，按核类型取最晚完成，多个同分支模板取中位数。控制、同步或等待无法单独辨识时会随参考模式迁移。 |

950 的实际库实现决定块大小、对齐和分支。公式中的首发 cycles、固定发起成本、持续端口速率、同步交接和排空，分别来自可定位的 CA 时间戳、指令组计数及连续页斜率。部分路线只识别到组合成本。970DT 的核数、频率、各精度峰值、HBM 与 L2 使用目标配置。未知的 MTE、UB、发起 cycles 等沿用参考假设，可被调用方覆盖。配置中记录值的来源。提高 HBM 容量本身不会提高字节率。[逐芯片配置](../src/operator_model/data/chips/) · [分阶段校准参数](../src/operator_model/data/parameters/)

### 理想算术与 CA 阶段时间

`理想算术 cycles = 对齐后运算量 / 对应精度的每核峰值(ops/cycle)` 给出满吞吐的算术基准。BF16 Matmul 在 950DT 的 [1,256,1024] 开发窗里，一片有 524,288 ops，理想算术是 64.08 cycles。CA 量到首条 MMAD 发起至退休为 171 cycles，首发到次发为 162 cycles。模型分别对这两类观测扣掉理想算术并做统计，得到不同的退休和发起残差。跨代把算术项改用目标峰值，控制残差在实现相近时先继承。若同一路线的残差随片工作量持续增长，可以进一步用多个片工作量分离固定延迟与有效吞吐。[MMAD 的观测与复算](examples/matmul.md#从-17-个开发窗复算-bf16-参数)

### 缺少目标 MTE 或 FIXP 数据时

以普通 BF16 Matmul 为例，970DT 沿用 950DT 开发窗的每核有效速率，MTE2 为 47.15 B/cycle，MTE1 为 180.65 B/cycle，FIXP 为 158.30 B/cycle。首读响应、首片依赖和写尾排空同样以 cycles 继承。配置显式给出端口带宽时，用 `GB/s / GHz` 换成 B/cycle。FIXP 的默认速率来自末条 MMAD 退休到关键核结束的拟合，表示本条写出路径的有效成本。其他算子可用不同的参考速率。

用目标容量、核数和实现规则重新计算每核字节数和共享字节数。局部读写服务用本地 B/cycle，聚合服务用目标 L2、HBM 的 B/cycle。在同一搬运阶段，满足最慢的本地或共享约束，再按发起和缓冲依赖排程。970DT 例子的 MTE2 受本地端口限制，FIXP 受共享 L2 写入限制。缺失的片上容量沿用 950DT，这些跨代参数及同实现假设都属于外推条件。[Matmul 搬运的数值复算](examples/matmul.md#同一-shape-外推到-970dt) · [970DT 配置](../src/operator_model/data/chips/Ascend970DT.json)

### 什么时候掩盖，什么时候暴露

模型先定每段自己的服务 cycles，再排它何时可开始。一个普通依赖事件可写成 `开始 = max(所需数据就绪, 执行资源可接收下一项工作, 缓冲槽可复用)`，`完成 = 开始 + 服务时长`。流水资源可接收下一项工作的时刻由发起间隔决定。两个工作都必须完成且可以并行时，后继由较晚完成的那条支路决定。

- **首块与稳态。** 第一块要先读再算，两段都进入关键路径。有双缓冲后，下一块读可以和当前块算重叠。950PR Matmul 的后续页读服务为 2780.01 cycles，当前页计算为 4494.78 cycles，读在这个计算窗口内就绪，因此页间隔由计算决定。若读服务升为 5000 cycles 且其余相同，Cube 要多等约 550.22 cycles。[Matmul 页间隔](examples/matmul.md#首轮稳态和尾波怎样重叠)
- **末块和共享下界。** RMSNorm 前面各块的写回可以和后面各块的计算并行。950PR 的 [8192,5120] 写描述符并集为 36478.729 cycles，可被前面的计算掩盖 35855.868 cycles，约 622.861 cycles 露在尾部。共享读写仍需检查 L2/HBM 能否在排程窗内搬完，只有排程窗覆盖不了的部分才补入总时间。[RMSNorm 写回算例](examples/rmsnorm.md#计算怎样掩盖写回)

因此，公开的 `stages_us` 表示各实现按自身排程分给整窗的增量。资源在途区间或忙时要看诊断和 CA 时间线。两个引擎可以各自忙了很久，同时只给整窗贡献一段时间。[各阶段公式与流水图](pipeline-comparisons.md)

## 每种实现的工作量和时延

以下给出公开默认调用的主要计算步骤。符号 ⌈x⌉ 表示向上取整，pad(x,g)=g⌈x/g⌉ 表示按粒度 g 补齐。每条链接提供具体输入、调用代码、两端模型与 CA、970DT 外推，以及分块或不可辨识的部分。

### Vector 与行归约

**DynamicMXQuant** 接收 BF16 的 R 行 C 列，每 32 个值共享一个 scale。令 G=⌈C/32⌉ 为一行的量化组数，取绝对值和求最大值共需 R(2C−G) 个标量等效操作。有效读 2RC B、写 RC+2R⌈C/64⌉ B，scale 按两个一组打包。每行归约可沿组边界分核。UB 先保留 2048 B，剩余空间按八组的输入、输出、临时区与双缓冲容量选择行块和列块。每个工作块按读、VF、量化输出与 scale 写回调度。同一写粒度中的多个 scale 写者可能竞争，只将暴露的等待计入尾部。DT 常规形状使用参考核指令计数/阶段斜率及短片段修正，其他芯片和超大行轴用目标资源模型。真实片外读写混合效率在超 L2 的工作集上仍是主要误差源。[量化算例](examples/quant.md)

**RMSNorm** 对每行求 s=1/√(Σx²/D+ε)，再输出 y=x·s·γ。T 为行数、D 为每行通道数，ε 是调用约定的稳定常数，γ 为共享权重。BF16 主输出为 2TD B，FP32 的 rstd 为 4T B。按行分核，行宽和可用 UB 决定每块行数。估计平方、分组归约、倒数根、归一化、主输出和统计量写回。最后一块可使 SIMD 与 MTE3 部分重叠。短流水区分读请求开始、返回、向量就绪和写退休。较多 UB 轮次采用稳态分摊。未知前序默认点与实际有前序的条件估计分列。[RMSNorm 算例](examples/rmsnorm.md)

**Cast BF16→FP32** 将总元素数 X 展平，读 2X B、写 4X B。最忙核的元素按 UB 容量切成 U 个 tile。首块包括控制、读、转换和写，中间块取读端口、写端口、向量转换及双缓冲槽复用的最大间隔。L2 能保留的脏输出和目标共享端口限制全片收尾。转换类向量操作的名义计数不能直接用 FP32 FMA 峰值定价。[Cast 算例](examples/cast_bf16_fp32.md)

**FP32 Sigmoid** 对 X 个输入计算 1/(1+exp(−x))，各读写 4X B。按最忙核的 UB 块长度 n 把向量工作换成 ⌈n/64⌉ 个 FP32 向量组，组启动和稳态间隔使用对应指令观测。双输入与输出槽受 max(读纯服务、写纯服务、向量服务、共享字节服务、输入槽占用/2、输出槽占用/2) 限制。末块短于满块时单独推算。[Sigmoid 算例](examples/sigmoid_fp32.md)

**MoE Gating Top-K** 输入 T 行、每行 E 个专家，选 k 个。FP32 分数和一次偏置读共 4(TE+E) B。权重和 int32 ID 共写 8Tk B。当前合同固定 sigmoid、单专家组和偏置选取。每核心负责最多 ⌈T/Cv⌉ 行，Cv 为目标 AIV 数。每行排名的等效工作是一项固定成本加上与 ⌈E/64⌉ 成正比的组成本。两种专家宽度下读就绪到首次写的 DT cycles 确定这两项，按目标每核向量能力缩放。Top-K 比较与索引工作未完全计入名义 FLOP。[路由算例](examples/moe_gating_top_k.md)

**AttnResFwd** 输入 [T,D,S,N]，T 为 token 数、D 为通道、S 为 bank 的槽容量、N 为有效残差数。按请求属性确定要读取的 bank、前缀、权重和要写回的张量。每行的向量迭代随 ⌈D/64⌉ 增加，候选打分与混合工作随有效 N 增加。按权重与输入载入、候选评分、归一化、输出组合、写回的依赖定价。同核后续行可复用权重。write_idx 和 materialize 改变读写合同。驻留 prefill 分支复用同族已测子阶段，完整同合同测量缺失的部分单独标记。[Attention residual 算例](examples/attn_res_fwd.md)

### Cube 与分 K

**Matmul** 使用 [M,N,K]，A[M,K] 乘 B[K,N]，有用计算 2MNK，连续 BF16 下逻辑读 2K(M+N) B、写 2MN B。以 (bm,bn) 为输出块时母块数为 ⌈M/bm⌉⌈N/bn⌉。普通路径重算尾波矩形、L1 K 页与 L0 片段。分 K 路径先选择输出组数，再给同一组分配 K 片，由 AIV 合并 FP32 部分和。长 M、窄 N 的权重能在 L1 时按“首载 B、连续 A、输出写回”定价。共享混合读写和 L2 可容纳的脏输出会让 4 倍行数对应的时间超过 4 倍。大形不逐条枚举 MMAD，合并相同波段。[Matmul 算例](examples/matmul.md)

**Addmm** 的连续 BF16 列偏置合同为 Y=AB+b，b 长 N，α=β=1。乘加量仍为 2MNK。有效读在 GEMM 基础上多 2N B，额外逻辑加法 MN 次。使用带偏置的输出矩形和目标 AIC 波次，内核把偏置并入 MatMulV3，阶段归属由已装库决定。其它 bias 广播方式及不同缩放系数需要独立合同。[Addmm 算例](examples/addmm.md)

### 稠密 MX Matmul · 乘加与权重展开

目标是同一张量语义下的两种实现。A4W4 把两个打包 FP4 输入直接送入带 scale 的 Cube 运算。A8W4 在同一个 kernel 内由 AIV 将 FP4 权重展开为 FP8，再由 AIC 消费 A、展开后的 W 与尺度。共享的算式为 `2MNK` 个有用操作、`2MN` B 的 BF16 输出。若 A 每个值占 `b_A ∈ {4, 8}` 位，张量逻辑读量为

```text
R = M × ⌈K×b_A/8⌉ + N × ⌈K/2⌉ + (M+N) × 2 × ⌈K/64⌉
```
前三个加数分别是 A、W 和两份 E8M0 尺度，单位均为字节。第三项来自每 32 个值一组、两个 scale 成对存储。A8W4 的片上展开单列为实现工作量，写回全局内存的仍只有最终输出。

给定目标的整域稠密峰值 `P_b`（TOP/s）、AIC 数 `C` 和主频 `f`（GHz），每核每 cycle 的乘加工作价格为 `q_b=1000P_b/(Cf)` 个标量算术操作。A4W4 用 `q_4`，A8W4 用 `q_8`。模型先用活动核数切分工作，再以忙核的实际分块定价。分块尾部造成的补齐工作计入执行服务，不改变 `2MNK`。每次传输在每核端口、共享 L2、片外接口分别计算“字节 ÷ 每 cycle 字节”，取最慢约束；L2 中可复用的重复读和仍驻留的脏输出单列。运行时的 `work` 给出有用工作，`projection` 给出定价用的片上流量、启动、关键路径阶段和分核假设。

**原生 A4W4 分块。** V3 的基础块上限是 256×256，工作不足一波时按 AIC 预算重分长轴。`K_0` 表示一个 L0 MMAD 片深。有足够的初始网格时使用库的默认 256（短 K 按 64 对齐），否则按 A/B 两条 L0 的双缓冲容量，以打包行的对齐粒度选择深度。`K_1` 是 L1 页深，可包含多个 `K_0`。按 L1 可容纳的数据和 scale 窗口分组；单个 M 网格、跨 N 多轮且能驻留时复用 A。尾波还有 `r` 个母块而可用 `C` 个 AIC，驻 A 分支沿 N 把每块分为至多 `⌊C/r⌋` 份，以真实列数计搬运，Cube 计算另作对齐。各核完成自己的前块后可继续，无需全片波间栅栏。例如 PR 的 [11,8192,1536] 首波 28 个 256 列块，剩余 4 个母块各分 7 份，得到 24 个 37 列、4 个 34 列的矩形。[V3 MX 滑窗](https://gitcode.com/cann/ops-nn/blob/28d19e078fd2d4144a681eb20ed3261047256d0c/matmul/quant_batch_matmul_v3/op_host/op_tiling/arch35/adaptive_sliding_window_mx_basic_api_tiling.cpp) · [矩形直方图、读服务与时间算例](examples/mx-native-tail.md)

**混合 A8W4 分块。** 950 安装包的 ND、转置 W、MX 权重 prologue 对应 Blaze SWAT。模型复用 9.2.1 host 规则的整数计算：按最多 256×256 的母块先算输出网格。如果还不到一波，就沿较长轴按整数核预算分配，把候选边长向上对齐 16，再用实际对齐尺寸重算块数；根据长宽比例调整网格。随后按边缘合并、末波拆块、有效非空子块和 L0/L1/UB 容量生成工作矩形的频数表。设 `G` 为该表所有矩形的个数，`C` 为目标可用的 AIC 数，工作核数为 `min(C,G)`，忙核轮数为 `⌈G/min(C,G)⌉`。完整的重复波用计数定价，仅末波按核展开，预测开销随末波参与核数变化。[9.2.1 的 SWAT host solver](https://gitcode.com/cann/ops-nn/blob/28d19e078fd2d4144a681eb20ed3261047256d0c/matmul/quant_batch_matmul_v4/op_host/op_tiling/arch35/quant_batch_matmul_v4_weight_quant_mx_swat_tiling_solver.cpp) · [在线实现](../src/operator_model/operators/matmul/mx_swat.py)

以 PR 的 [2048,128,256] 为例，初始 256×128 有 8 块。N 只需一列，M 先分 28 份，每份 `⌈2048/28⌉=74` 行，对齐后为 80。最终 25 个 80 行块加一个 48 行块，各占一个 AIC。末波若对每个块再分两份，就超过 28 个可用核。每个块需要展开 128×256 个权重，故 UB→L1 共 `26×128×256=851,968` B。v1.2 枚举 2 的幂次子网格时排除了 26 行网格，只给 16 核。此修正通过几何和缓冲条件作用于相同库路径。[PR 分核与流水算例](examples/mxfp4-design.md)

**区分 L1 页、L0 片段和 AIV。** `l1_page_k` 是当前 L1 页的 K 深度，`mmad_k` 是 L0 乘加片段深度，两者之比决定一页内的片段数。混合路径的 host 规则先尝试两个 L1 槽的矩形方案，再检验四槽方案和最小块后备方案。检查分开的输入、scale、L1 固定分银行、L0 与 UB 展开缓冲的字节预算。两槽时 AIV 按页轮换，同一页的首发和展开由一位生产者支付；跨页可以并发。四槽时，若 N 切分后的第二个片段非空，两位 AIV 可以同时生产一页。`launched_aiv` 计发射的 AIV，`weight_producer_aiv` 计有展开工作的 AIV。970DT 采用 1:1 资源情景，由一位 AIV 承担相应工作。具体实现是否沿用该交接方式仍待目标芯片验证。

**混合路径只有一页时。** 分别算读、展开、交接、L1→L0 和 Cube 的服务耗时。若每核有 `U` 个 FP4 值需展开，可用 `50+22U/V` 估算一位生产者的转换耗时；`V` 是目标每 AIV 每 cycle 的 8-bit 峰值等效操作数。50 是启动 cycles，22 是每值的峰值等效工作量，来自 950 开发 trace 中首次 Vector 到首次 UB→L1 的区间：4,096、8,192、16,384 个权重分别约 226、402、754 cycles。这个等效工作量由两端的 950 Vector 峰值与实测权重/cycle 的比值得出。真实解包包括移位、掩码、交错和存储。L1 交接另付端口字节成本与约 158 cycles 的暴露延迟。把源与目标的这两项资源分开，970 的 4-bit Cube 峰值增长就只会直接加速原生路线的乘加。

**多页 A8W4。** 设页的有效宽、深为 `w,d`，目标每 AIV 每 cycle  FP8 等效操作数为 `V`。每个 256 B 寄存器可装 512 个 FP4 值，按行展开的预算为 `T_v = 50 + w × max(11, 7.5 × ⌈d/512⌉) × 512/V` 个 cycles。11 是每行的发起成本，7.5 是每次寄存器重复的成本，512 是校准时的 950 每核峰值参考。先分别计算激活页、权重页的读取和 AIV 处理。交接要等本页展开结束、该 AIV 的传输端口可用，以及当前 L1 槽释放。槽在其上一页**最后一个 MMAD 发起**时可复用。随后算 `t_issue = max(t_Cube可发起, max(t_A,t_W) + L_0 + D_0)`，其中 `t_A,t_W` 是当前激活及展开权重在 L1 就绪的时间，`L_0,D_0` 为首个 L0 片的固定延迟与字节服务。页内的后续 MMAD 受装载端口、Cube 服务和最短发起间隔的最大值约束。满占用时末核发起离散度的先验是 2680 cycles，按 `(C_a−1)/max(1,C−1)` 缩放；`C_a` 是活跃 AIC、`C` 是目标 AIC 总数。首读之后，复用槽时的激活读响应采用 150 cycles 的可见残余（受配置首响应上限约束）。两数来自已有 950 窗，跨代继承有不确定性。重复整环使用 max-plus 递推的精确幂，尾页按实际尺寸算，避免线性枚举所有页面。[逐事件递推、参数样本、芯片对照](examples/mx-handoff.md)

**多页 A4W4。** 设主矩形全部读服务为 `R_T`、首 L1 页读服务为 `R_1`、全块及末片的 L0 搬运成本为 `D_T,D_e`。每输出块有 `q=⌈K/K_0⌉` 条 MMAD，首片 Cube 成本 `F_1`，最短发起间隔 `I_c`。主要服务成本取 `max(R_T,R_1+max(D_T−D_e,(q−1)×max(F_1,I_c)))`。这允许后续页的传输和先到片段的乘加并发。成本按 cycles 算，最后加首响应、装载、末次 MMAD 退休、写尾和不能被隐藏的共享链路预算。多页读的持续速度缺省 87.23 B/(AIC·cycle)，取 7 个旧端点的相邻页退休间字节服务中位数；显式目标 MTE2 带宽可覆盖。后续窄尾块按其自身读、装载、乘加和写成本的最大值追加，驻留的 A 不再从 GM 重读。设备微秒为总 cycles 除以 `1000f`，`f` 的单位为 GHz。[完整数值与分阶段解释](examples/mx-native-tail.md)

小形状的首发、读响应、装载和写尾来自 N=128、K=256、M=1 或 256 的 DT/PR 开发窗；多页读服务、解包和槽复用另使用既有真实投影的分阶段 trace。原生从首次有载荷的 MTE2 开始分析，混合从生产 AIV 的第一次权重读取开始。用首 MTE1 或首 Vector 去除页服务估算读响应，用末 MMAD 核的装载至乘加、发起至退休分开估算装载和 Cube 固定延迟，用整窗结束减去末 MMAD 退休及写服务估算写尾。两个开发形在同一 SKU 取阶段 cycles 的中位数；对未知芯片只转移两芯片合并后的 cycles 先验，再按目标重新计算工作量、吞吐与频率。每核 MTE 价格与稳态发起间隔仍可由目标配置指定，缺省借用已有 Matmul 价格。N=128、K=256、1≤M≤2048 且资源与内置 950 完全一致时，公开接口可返回 `estimated`；这一条固定 N/K 线上实测了 M=1、9、256、2048 四个点。真实投影几何的独立实测覆盖和同集误差见总误差表。其他可定价几何与 970DT 返回 `extrapolated`。[逐参数阶段系数格](../src/operator_model/data/parameters/mx_matmul_phases.json) · [逐步算例、CA 与流水图](examples/mxfp4-design.md)

旧投影用于验证上述几何和依赖，未用于本版调参的真实投影单独报告核数、两端耗时和配对加速比。不同精度的最差 shape 以及无法由本批观测唯一分解的等待均列在[冻结独立误差分析](error-analysis.md#稠密-mx-matmul--双端同形验证)。

### 注意力与状态递推

**稠密 FA** 的轴为 [Q,L,D,B,H]，依次为查询长度、KV 长度、头维、batch 和本地头数。QK 与 PV 各算 `2BHQLD` 次有效操作。按 batch、head 和 query 行块分 AIC，同一任务遍历 KV 页。本路线覆盖 BF16 稠密非因果 SBH、D=64/128。

一页有 `m` 行 query、`n` 个 KV、头维 `d`。记 `x16 = 16×⌈x/16⌉`，每种矩阵乘工作 `F=2×m16×n16×d16`，每种乘法的指令片段数 `u=⌈n/128⌉`。设最忙 AIV 处理 `r` 行，`P_C,P_V` 分别为每 AIC 的 Cube op/cycle 与每 AIV 的 Vector 等价 op/cycle，`R,R_1,R_F` 分别为读、片上装载、结果搬出的有效 B/cycle。六项 cycles 需求为

| 资源 | 每页 cycles | 物理或观测口径 |
|---|---|---|
| Cube | `2×F/P_C + u×(h_Q+h_P)` | 两次矩阵乘共享 Cube。`h_Q,h_P` 是每个 QK、PV 片段在理想运算之外的实测残余 cycles。 |
| Vector | `(5×r×n + 3×r×d)/P_V` | 繁忙 AIV 的 score 处理与输出更新，按两类工作的等价单位计价。 |
| K/V 读 | `4×n×d/R` | 两个 `n×d` 的 BF16 张量。Q 在首轮单独搬入。 |
| MTE1 | `2×(2×n16×d + m16×(d+n16))/R_1` | 两次乘法各自要装载两个操作数，使用片上布局字节。 |
| FIX | `4×m16×(n16+d)/R_F` | 两个 FP32 中间结果，由各自输出矩形得到字节量。 |
| 发起控制 | `J×u/2` | `J` 是开发 trace 的 256 位置双片段持续发起间隔，由 K、V 页首发时刻随页号的斜率得到。 |

同一资源内的工作相加，可以并发的资源取最大，给出页启动间隔 `I`。首张页分别等 Q/K 就绪、QK 与 softmax 完成、V 到达，再启动 PV。首轮后只增加后续页的间隔，最后单计向量更新和写回。950PR 的 [9,131072,64,1,1] 有 512 张满页，六项中发起控制给出 853.405 cycles/页，511 次续发占 264.297 µs。逐项代入、工作来源、吞吐价格的提取与最后的全窗核对见[FA 算例](examples/fa.md#一页里有多少工作)。

**LightningIndexer** 输入 [B,Q,L,G,D]，G 为索引头数、D 为头维。每个有效 query–key 对做 G 次点积、ReLU 和 head 加权归约，再从整行分数取 top-k。设 P 为 mask 后合法配对数，则有用 Cube 工作为 2PGD。单波稠密 BF16 路线每四 query 组成一组，每页 128 个 key，首先按实际可见 key 数算页数。页发起间隔取目标读端口和补齐后的 MMAD 服务两者较大者。组内向量排序一片最多 8192 个 key，另有 Cube→Vector 交接和末笔输出。多组可能共享缓存中的 K。多波与不同布局的证据另计。[Indexer 算例](examples/lightning_indexer.md)

**单链 Recurrent KDA** 接收 [B,S,Hq,Hv,K,V]，S 为时间步数，K/V 分别为键宽和值宽。一条状态是 K×V 个 FP32 元素。每一步必须读取前态，做门控、键与状态收缩、秩一更新，再用 query 读出。每步主要计算随 KV 增长，共享状态使同链的 S 步串行。用单 AIV 上的状态更新工作单位 S·K·V/16384，按参考 CA 的 SIMD、MTE2、MTE3、Scalar 等独占阶段分别计固定项与单位增量。已校准合同是 B=Hq=Hv=1、K=128、V=128/256、S≤8。多链情景与单链校准分开。[Recurrent 算例](examples/kda_recurrent.md)

**Chunk KDA（FLA 三段实现）** 以 64 token 为一块，块数 J=⌈S/64⌉。对每个头和长度 n 的块，因果块内的有序对数为 n(n+1)/2，末块用其真实长度。Prepare 生成块内系数和中间结果，FwdH 沿块序逐次更新 K×V 状态，Finalize 使用块内结果与入态生成输出。Prepare/Finalize 可跨头和块并行，FwdH 的同一头相邻块存在状态依赖。时延为三个已同步设备窗之和，按各阶段真实 tiling 重算排程。默认 dispatch 若选择另一个融合实现，该路径的正确性、同步和设备时钟须单独核验。[Chunk KDA 算例](examples/kda_chunk.md)

### mHC 的组成与外层调用

T 为本次 token 数，N 为残差流数，D 为每流宽度，I 为 Sinkhorn 迭代次数。每个 token 的 N×D 输入展平后长 ND，投影输出宽度 O=N²+2N，分别用于残差矩阵与两组门控。

**内置 mHC Pre**。主投影的有用 Cube 工作为 2T·ND·O，向量工作包括倒数 RMS、两个门控及 N 路输入混合。分支根据短 M、长 K 是否需要拆 K 来定价。读写中保留实际合同要求导出的中间张量。在阶段归属不唯一的路径，使用参考核上互斥的计算、搬运、归约和控制区间作为时间预算。每个预算段的累计位置不能解释为单指令发起点。[Pre 算例](examples/mhc_pre.md)

**独立 mHC Sinkhorn**。每个 token 输入一张 N×N FP32 矩阵，数据读、写各 4TN² B。连续的行、列归一化各遍历 N² 个元素。I 轮有 2ITN² 个除法等效工作。按矩阵行分 AIV，最忙核的矩阵分到寄存器组，N=4 时一组最多容纳八张矩阵。组固定 VF 发起与组内迭代分别定价，同一矩阵的下一次归一化等上次结果。未知前序与已知前序有两种计时解释。[Sinkhorn 算例](examples/mhc_sinkhorn.md)

**内置 mHC Post**。yₜⱼd=postₜⱼ·hₜd+Σᵢresₜⱼᵢ·xₜᵢd，i、j 均在 N 个残差流中遍历。带残差矩阵时每个输出有 N+1 次乘与 N 次加，共 TND(2N+1) 次有效操作。小 T 且 D 宽可沿通道切片，行数多时按连续 token 分核。输入到达、SIMD 混合和 MTE3 写出随前序变化。仅 shape 的点估计在两个 950 目标上均有超限样本。调用方若能看见相同流的前序，可记录 AIV 高水位并按顺序调用。[内置 Post 算例](examples/mhc_post.md)

**vLLM HcPost**。使用显式 implementation 选择 arch35 扩展，输入为 [B,S,4,D]，T=BS。其算法量与四路混合相同，库将 token 均衡分到 AIV，核内对 D 再切块。按实际控制器、读入、向量混合与写回队列的双槽依赖定价。计算首块、稳态和尾块后与全片共享带宽下界取较大者。默认标注实验性，目标形状的数值、收尾和全核身份均应单独确认。[扩展 HcPost 算例](examples/hc_post_vllm.md)

**融合 mHC PreSinkhorn**。一次 kernel 完成投影、生成系数、稳定化和 20 轮归一化。小 token 合作团队与较多 token 的分队方式可能不同。从 T、N、D 算每个团队的投影片段数与两段向量工作，分别定位末条 MMAD、交接和最后一组 VF。固定 I=20、D=4096 的已校准 BF16 调用含 HF32 投影。不要把 BF16 GEMM 的峰值直接代入这一段。[融合 PreSinkhorn 算例](examples/mhc_pre_sinkhorn.md)

**拆分 mHC 链**。实现为三个串行库调用，T链=TPre+TSinkhorn+TPost。取同一 shape、相同辅助输出合同下三个子窗。中间结果在接口处既写又读。残差混合之外的 attention、MLP 和 host 时间由系统另计。与融合 PreSinkhorn 是可选择的实施方式。[拆分链算例](examples/mhc.md)

### MoE 专家计算

输入 [T,K,F,E]。T 是本 rank 实际接收行数，K 是 hidden 宽度，F 是本地专家中间宽度，E 是本地专家数。mₑ 是第 e 个专家行数，Σmₑ=T。对每个非空专家分别向上取整，计算输出块数，避免把两个专家的尾行当作同一块。现行验证使用普通 ND MXFP8 权重与 E8M0 尺度。参数中给出 expert_counts。业务权重若为 FP4 或采用不同布局，应使用相应实现的证据。

**GroupedMatmulSwigluQuantV2（GMM1）**。上投影为 K→2F，共 4TKF 个有用 Cube 操作。再做两支输出的 SwiGLU 及逐 32 元素 MX 量化，写出 TF 个量化值与配套尺度。输出列宽 o=2F。参考策略中行块 16、列块 128、K 粒度 64。先算 Σ⌈mₑ/16⌉·⌈o/128⌉ 个输出块，再按目标活动 AIC 算波次。AIV 按中间激活与 scale 块。按实际重叠区间给流水计价。[GMM1 算例](examples/grouped_matmul_swiglu_quant_v2.md)

**GroupedMatmulV5（GMM2）**。下投影 F→K，共 2TFK 个有用 Cube 操作，输出 TK 个 BF16。源、目标轴与 GMM1 对调，列块数为 ⌈K/128⌉，每个块的 K 向工作随 ⌈F/64⌉ 增加。MX MMAD 的有效维度从设备指令核对，不用“活跃核数×整块”替代尾块工作。底层库的专家碎片和同步仍限制跨代模板精度。[GMM2 算例](examples/gmm2.md)

**MoE FFN 两段**。组合为 TFFN=TGMM1+TGMM2。前一段的量化输出和 scale 直接成为后一段输入。接口逻辑字节包含这些中间结果，实际去 HBM 的字节数要另有缓存或控制器证据。专家选择、token 分发/回收和卡间通信均由上层调度。[完整 FFN 算例](examples/moe_ffn.md)

### 如何复算例页里的微秒数

读算例时可沿一个中间量往回查。先看模型把 shape 切成多少任务、哪一核或哪一页决定完成时间。然后在该核上计算工作量 `W`（字节、补齐后的运算或发起次数），找与单位匹配的价格：若是吞吐 `R`，cycles 为 `W/R`；若是每次发起的价格 `c`，cycles 为 `Wc`。芯片配置给出的峰值、trace 测出的有效速度、从阶段时刻扣除已知服务后得到的残差，物理含义各不相同。最后依照依赖取和或最大，将暴露在关键路径上的 cycles 除以 `1000f_GHz` 转成 µs。对直接以 µs 拟合的阶段保留其原有单位。下面的算例按实际使用的预算方法分组。

## 校准范围、查询与解释

先核对输入、调用身份、分支和全部数值输出，再核查每核窗口、MMAD/VF 次数与输出覆盖。单 kernel 参考时间取全片最早指令到最后退休。多个串行 kernel 只有在明确归属同一调用时才求和。首发/退休的 wrapper 包络、未结束的 trace 前缀以及 970DT 外推各有独立标签，不能混进同一个指令误差分母。WAPE=Σ|预测−CA|/ΣCA，最大误差取每一合格窗口的最大 |预测/CA−1|。用于选参数的窗口归为回放。冻结后独立测量需保留冻结资格。

在线预测多采用闭式分块、按波次分段或模板聚合，无需构造真实张量。部分路线的开销会随专家数、query 组数或剩余块数而变。设备段重叠时，模型返回的互斥成本、起止时刻与资源利用率有不同含义。利用率按有用运算/（预测时延×目标峰值）计算，是整片有效利用率。要研究单核负载，需结合活动核、尾波和对齐后的工作量。没有可辨识数据的阶段或物理 HBM 流量，保留未知值。[设备时间、查询墙钟与适用范围](error-analysis.md) · [正式校准数据](../calibration/reference/windows.jsonl)

## 容量如何改变一次预测

下表固定 950DT 的核数、频率、端口速度，在 `timing_mode="resource"` 下每次只改一个容量。数值是模型的敏感性实验，容量修改后的目标没有对应 CA。容量决定能分几块、哪些数据可留在片上；模型会重新安排可以重叠的阶段。

| 算子与本卡 shape | 配置变化 | 资源模型的响应 | 原配置 → 新配置的设备 µs |
|---|---|---|---:|
| Quant [8192,5120] | UB 248 → 64 KiB/AIV | 最忙核的 tile 从 7 行变 1 行，轮次 19 → 128 | 29.011 → 75.366 |
| Matmul [1280,2048,512] | L1 512 → 256 KiB/AIC | K 页从 256 变 128，每页更短，模型对页间重叠的估计也改变。这一形状暂缺缩小 L1 的 CA 来确认快慢方向 | 12.449 → 12.018 |
| Cast [262144,128] | L2 128 → 32 MiB/域 | 输出在 L2 中可保留的部分变少，更多结果暴露在共享写回路径上 | 36.368 → 57.551 |

对系统调度，令 `T_d` 为设备首条指令至最后退休的模型时间，`n` 为该合同的物理 kernel 发射次数，`h` 为每次发射在设备窗外串行暴露的时间。两者均以微秒计，顺序执行的系统占时为 `T_s=T_d+nh`。配置省略时 `h=0`。有流水化宿主队列的系统可独立调度提交与设备事件。[`h` 的输入来源与接口](integration.md#每次发射的额外开销和片上容量)

SIMPlatform 的精细后端把 `T_d` 作为本卡节点时间交给 DES。节点的张量合同决定能否替换原价格，平台的图依赖决定单轮时延。以 128 Ki decode 捕获为例，专家乘的实际精度与量化的首发延迟可使单轮差值出现不同方向。[接口、配对实验及两个实际节点的复算](sim-platform.md)

## 没有目标实现或改变精度时怎样建模

公共入口按算子、精度、布局与属性选择实现。相近算子可共用分块与资源价格，例如 BF16 Matmul 与列 bias Addmm 共享部分 Cube 资源模型；Addmm 仍有自己的尾部工作。Quant 与 RMSNorm 都在 Vector 上运行，但后者需要跨行内元素完成归约，前者可按 32 元素的组推进。已有公开算子名不会自动覆盖所有 dtype。

新算子先写张量算式、输入/权重/scale/累加/输出类型与布局。再列出可行实现：由哪个单元消费每个张量、是否需要解包或格式转换、哪些阶段可流水、何时必须同步。根据容量选 tile、计尾块与忙核，按目标资源为每段定价。来源区分为格式规范、相邻代源码/trace、目标芯片规格和实现假设。仅有算式时可报告运算量、字节和条件下界；有可说明的指令发起和端口服务模型才给带假设的端到端外推。真实新内核出现后可替换实现策略并增补独立 CA 或硬件校准。[MXFP4 Matmul 的完整推导演示](examples/mxfp4-design.md) · [已支持实现的流水对照图](pipeline-comparisons.md)

FA 的 Q、KV cache 与 softmax 内部精度，以及 MoE 两个投影的权重格式和在线预处理，需要逐合同确认。[其他精度路线及校准入口](precision-coverage.md)
