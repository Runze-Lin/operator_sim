# v0.2 误差归因与下一轮验证边界

本轮时延目标并未全部达成。新留出整体 WAPE 为 7.25%，但 quant 为 13.85%，超过预设的 10% 目标。matmul 为 6.91%，FA 为 4.47%。7/7 留出点核数匹配；这只验证了这些输入的分核结果，不证明完整 tiler 已复刻。

固定耗时基线整体 WAPE 为 5.92%，其中 quant 7.27%、FA 3.21%，仍优于当前模型。matmul 则由固定基线的 12.82% 降至 6.91%。因此不能仅凭整体低误差宣称模型优于简单基线，也不能把这里的经验 Roofline 比较直接当成优于用户原始 Roofline 实现的证据。

## quant：工作量正确，流水缩放不足

| 输入 | 用途 | 每核 UB tile / 轮次 | 最大核 RV_* 次数：预测 / CA | 预测 μs | CA μs |
| --- | --- | --- | --- | ---: | ---: |
| [1024,4096] | 校准 | [8,4096] / 2 | 11896 / 11896 | 8.0439 | 8.0473 |
| [640,4096] | 新留出 | [5,4096] / 2 | 7480 / 7480 | 7.4579 | 6.2176 |

同样使用 64 AIV 和两轮 UB，留出点却高估 1.2403 μs（19.95%）。指令次数几乎精确，说明这次误差不能简单归因于少算/多算 VF 循环。

最慢核的观测中，两个输入 Vector family 忙碌区间分别约 2.070、1.343 μs，MTE2 分别约 2.728、2.698 μs，Scalar 分别约 3.121、2.507 μs，PUSHQ 分别约 2.137、1.415 μs。这些流水存在重叠，不能相加作为关键路径，也不能从忙碌时间变化直接认定因果。

当前模型共享全体 quant 样本的阶段斜率，用单一 `fill + (loops−1)×max(stage)` 表达 UB 流水，并以一个大 UB 校准点拟合该机制。它未显式表达 Scalar/PUSHQ 的依赖、同一核内负载变化和 fill/drain 随 UB tile 改变的效应。现有证据支持“工作量预测较好，阶段重叠/头开销模型不足”这一定位；还不能唯一分离各项成本。

下一轮应先从已有两份 trace 提取每轮首尾、Scalar/PUSHQ 与 MTE/Vector 的依赖间隙，修正关键路径表示；只选择少数新的 UB 容量边界点作独立验证。不能把本轮 [640,4096] 加入拟合后继续把它当新测试。此处记录诊断，不改写已冻结的 v0.2 预测。

## FA：时延接近不代表指令模型正确

FA 新留出的 MMAD 次数 WAPE 为 51.28%：Q=129 和 H=8 两点各预测约 3.03 次、实际 2 次；D=128/KV=192 点预测约 6.05 次、实际 4 次。

校准点 `[16,1025,64,1,1]` 的模型预测 5 次 KV 外层迭代，采用“每次 QK/PV 共两条 MMAD”的基础特征值 10；CA 的 CSV 则记录 18 次 MMAD。这一差异拉高了全 FA 共享的指令计数系数，继而高估短 KV 的次数。推断需要区分外层 KV tile 与内部 Cube 指令拆分，不能用一个全局倍数覆盖两者。

该长 KV trace 的 18 条 MMAD 中只有 14 条携带完整 m/n/k，其余 4 条有时序但没有维度 detail。总次数可核实，不能补造缺失维度，也不能将 `executed_cube_flops` 的部分合计称为完整执行量。时延拟合使用忙碌时间与整体参考窗，不依赖该 FLOPs 字段，所以这一发现不会改变冻结的时延结果。

下一轮应分开表示外层循环、实际 MMAD 分段和尾块，再验证独立新输入。尚不能根据当前 FA 拟合参数可靠判断 A7/A8 的 Cube/Vector 瓶颈转换。

## matmul 与测量口径

两点误差分别 7.71%、6.29%，核数和最大核 MMAD 次数匹配。只有两个独立留出点，且 BF16 高性能路径范围有限，不能推断其他 dtype、转置、量化与 GEMV 路径均成立。

这些结果对比 CA 跨核指令时间窗，不是实卡、框架调度或整网时延。v0.1 仅做过每算子一组重复测量；v0.2 新点没有形成重复统计置信区间。不能把百分之几的差异解释为高置信度改进。

## 仿真与查询开销

新增 18 次采集尝试（17 次成功、1 次超时）共 23.02 分钟墙钟、7.41 CPU 小时、4.82 GiB 原始数据；两轮合计 40.81 分钟墙钟、11.53 CPU 小时。普通新点约 50–77 秒，大 quant 成功采集约 125–173 秒；失败尝试已计入开销。本轮止于既定 18 次预算，没有追加扫参。

在线查询未缓存 P95 44.02 μs、缓存 P95 0.98 μs，批量约 133 万次/秒。这是本机单进程 Python 库调用，不含每次启动解释器，也还不是接入用户系统仿真后的端到端数字。

冻结发生在系统 Python 环境，开销评估使用独立 Conda Python 3.12。重放检测到个别浮点累加结果相差约 10⁻¹⁵（指令数约 10⁻¹²）；评估允许 `1e-12` 相对/绝对舍入容差，文件哈希、输入和整数核数仍严格验证。误差统计始终使用冻结值，未在看见留出结果后调整参数。

完整逐点结果见 [评估 JSON](../results/v0.2/evaluation.json)，图表见 [误差图](../results/v0.2/holdout-error.png)。本版作为可复现的首轮开发基线保留，quant 时延和 FA 指令结构是明确未完成的准确性项。
