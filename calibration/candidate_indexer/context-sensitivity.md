# 候选 Indexer 对整批请求耗时的影响（950DT）

比较对象是同一份 rank 0 系统捕获。只更改候选节点的耗时，所有其他节点、依赖、执行资源和容量不变；分别执行离散事件调度，再沿相同的上下文位置对 prefill 与 decode 积分。秒数是部署情景的预测，没有端到端设备实测。

“原图”使用已发布的 BF16 全表评分资源排程；“仅候选旧价”在精细图上替换候选耗时，时长来自系统原 Roofline 对同一节点的报价。CSV 的 `legacy_whole` 才是连同其他算子、缺项和占位都按原后端运行的整图，不能与“仅候选旧价”等同。

“MX 场景”改用 MXFP4 稀疏候选评分，假定 Q 已量化、索引 cache 的 key 和 scale 已折叠；不新增上游格式转换，不删减图上已有节点，也不重新计算 KV 分配。PA 分页按每页 128 个位置的部署假设，表宽取任务配置的预留容量（prompt + 1,042），即先按请求选表行，保留所有已分配列；32Ki、128Ki、512Ki、1Mi 分别预留 265、1,033、4,105、8,201 列。后两组从第一个 prefill 块起即选标量地址路径，此前先验取每条记录 64 周期；现默认在宽表同一行片段的相邻 tile 上采用 950DT 单团队 31 个 MMAD 发起间隔的算术平均数 109,555/31≈3,534 周期，片段的首发和尾部仍由排程定价。单 tile 的片段没有相邻间隔。这 31 个间隔的前 8、中 7、末 16 段中位数分别为 5,428、2,749、2,459 周期；全行均值包含起步与续发，不代表硬件恒定带宽。[1Mi/B1 末块另算 0、64、256 周期](context-sensitivity-scalar.csv)，三者是参数情景，不是误差上下限。这是替换 consumer 的条件价格，不表示原 BF16 捕获图已经执行了生产内核。“同账本峰值／原效率”均在这个 MX 场景上重跑 DES；仅候选更换工作量与位宽，其余节点分别复用原图相应账本。原效率采用 Cube 60%、Vector 60%、HBM 80%。

Flash 有 11 组。原始采样锚点中 prefill 共 72 张图、288 个候选调用，decode 共 33 对 target/draft 图、198 个候选调用。另 22 组 Pro/Kimi 的完整算子清单没有候选调用，三条资源账本的阶段与请求结果逐组不变。表内每行代表整批请求，生成 1,024 个输出 token，包含 prefill 的第一个 token；TP 都是 8。

1Mi/B1 最后一个 prefill 块：候选 consumer 平均单次 6,211.3 → 9,262.1 µs（64 周期先验 → 指令间隔模型）；整块 DES 468,346.3 → 480,549.6 µs。实测包括[单团队开发窗](qsli-one-team.json)与冻结后的[32 行并发单波](prefill-wave.json)。直接用 84.792 µs 的独立单波外推 128 波，按两种启动假设得到 0.484 s 与 0.487 s，[同图复算](wave-chunk.json)。4,096 行整块仍为外推。


Flash 的 MX 情景对已采样内部位置进行插值检查，prefill 的最大偏差 4.979%，decode 为 0.026%。已采样位置之间没有逐块验证。



32Ki 的 prefill 逐块枚举，其余长度的 prefill 和 Flash decode 沿采样点分段线性积分。*1Mi 的 decode 在模型预置上限外，故总时间也含外推。CSV 的 anchor_check 是用保留的内部位置检查插值所得的相对偏差；它不衡量对真机的误差，也不能验证预置上限外的行为。
