# Flash MXFP4 QSLI 的跨核归并与首发

昇腾 950 的原生 QSLI 可以把一行候选 key 拆给多个 AIC/AIV 团队。各团队先把自己的位置和分数写回，由 metadata 分配的归并 AIV 负责该行的全局 top-512。单行测试中的 32 条 `MMAD_MX` 在两端都已核对；高估可并行性、低估局部写回及最终归并的时间，会导致即使算对了点积条数，也低估整窗。[六个开发窗的逐阶段观测](v112_merge.json) · [同集回放](v112_merge_replay.json)

## 读写和等待在哪里

沿同一 AOT 设备 ELF 跟踪每个 AIV，取本地分片位置/分数的最后一次 DMA 写、最终选取者的首个部分列表读、各轮 carry 和部分列表读、两次输出 DMA 和直方图指令。时间统一取全核最早首令为零点。六个开发窗包括每个 SKU 的短表与宽表两种 81 候选块输入，以及 1Mi 可见长度下的 2,048 候选块输入。[PC 识别与复算脚本](v112_merge_trace.py)

| 950 目标、候选数和表宽 | 首次 MMAD 发起（cycles） | 末次 MMAD 退休 → 最后一次局部列表写完 | 最后一次局部写完 → 归并首读 | 归并轮数 |
|---|---:|---:|---:|---:|
| DT，81，8 | 11,244 | 2,875 | 1,130 | 1 |
| PR，81，8 | 12,625 | 2,845 | 1,066 | 1 |
| DT，81，8,201 | 12,265 | 2,878 | 1,128 | 1 |
| PR，81，8,201 | 12,146 | 2,807 | 1,065 | 1 |
| DT，2,048，8,201 | 16,466 | 2,849 | 1,488 | 5 |
| PR，2,048，8,201 | 15,671 | 2,942 | 1,203 | 4 |

PR 合格采集的宿主属性和官方 metadata 均为 28 个 worker。4 个团队各做两个 tile，24 个各做一个，最终合并 **28 个局部列表**。DT 合并 32 个列表。归并 owner 的读指令站点各自执行了 28 / 32 次，末端写回站点各自执行 4 / 5 次。早期 PR 无 IPC 的数值回放报告 32 个 worker；区分两次运行后，旧收据的周期和输出校验均维持原值。[修正说明及回放数据](v112_merge_replay.json)

## 算法与价格

**分配工作。** 对每行的压缩可见长度先计算候选数量和 512-key tile 数。当每个 tile 都是满块，官方 metadata 对等成本 tile 迭代分配剩余工作。令 `R` 为剩余 tile，`W` 为剩余可用团队，分给下一个团队 `max(1, floor(R/W + 1/2))` 个，再更新 R、W。从团队区间切入某一行的位置统计这行贡献了多少份局部 top-k。对于短尾，官方按余下 key 的 64/128 元素边界修正 tile 成本，在线模型当前用满 tile 权重近似；返回的 `team_partition` 注明这一点。成本沿最多 32 段递增的候选 tile 数和活动团队查询，大 Q 时无需逐行展开调度。

**定价首发和分片排空。** 源 kernel 的分片路径使用 `T_first = T_control + T_gather + T_publish + T_ring_read` 估计首个点积的可发起时间。gather 包含解引用 PA 页表及取 folded K/scale，publish 表示写 GM ring，ring_read 是 Cube 读 ring。之前用普通 LI 的 8,568 周期估计控制部分。现在先从每个开发 trace 的首个 MMAD 发起时间扣去这三个资源预算，再取六个剩余值的中位数 11,064.844 周期。该剩余值含宿主接口以下的 kernel 初始化、流水准备及未能分离的首读等待。最大输入的首发仍偏晚，现有样本同时改变活跃团队、候选数和地址布局，无法单独识别其中一个因素的放大系数。

测得各端全核最后一条 MMAD 退休到最晚局部列表写完的中位数为 2,862 周期，作为跨核分片的一 tile 排空预算，已计入的 FIX、Vector、局部 histogram 成本抵扣。较大分片保留原先按 tile 数增加的 histogram 工作。局部列表全部可用到归并方首个 DMA 读包含同步、控制和指令发起，取六窗中位 1,129 周期。两个时间差均为设备事件间隔，其中可能包含等待和不同核间的开始时间差。

**定价最终归并。** 设一行分为 `P` 份，每份输出 `K = 512` 个局部赢家，分数 BF16、全局 ID 为 INT32，一个 entry 共 6 B。UB 工作区可容纳 8 份。软件每轮最多取 7 份新列表，除首轮外再读上一轮的 K 个赢家。故 `J = ceil(P/7)` 轮，合计 `E = K × (P + J − 1)` 个待归并 entry。对每个拆行的关键归并路径，以目标芯片 cycles 为单位：

| 阶段 | 计算式 | 参数含义和来源 |
|---|---|---|
| 输入 DMA | `J × 228.430 + 6E / r` | `r` 为目标单核 DMA 字节/周期；由实测首条输入 DMA 发起至最后一条输入 DMA 退休，扣除字节服务预算后取各轮中位。 |
| 选取与映射 | `(J × 1427 + (E/256) × 16.2) × s` | `s` 为参考/目标每 AIV 的 Vector ops/cycle 比。测量输入全部退休到输出 DMA 首发的间隔。轮内扫描结果键、做两趟 8-bit radix、对赢家取全局 ID。按不同的 256-entry 组数先取同组中位，再取组间斜率的中位，得到每组 16.2 周期和每轮固定 1,427 周期。此窗口也包含指令间依赖。 |
| 输出 DMA | `J × (151.633 + 6K/r)` | 每轮写回 K 个位置和分数供下一轮或调用方使用。实测输出首发至末次输出退休，扣除 6K 个字节的服务成本后按轮取中位数。 |
| 可发起归并的等待 | `1129` | 从全核最后局部写完成到归并 AIV 首读的控制与同步间隔，只计一次。 |

当有多行被拆开，metadata 会把这些行的归并分给不同 AIV，模型取最慢的一行，再检查调用级 IO/L2 下界。各归并任务共享带宽、部分结果与相邻行是否命中片上缓存、跨代依赖延迟还缺少独立计数器。用于 970 的是目标频率、服务率和核数，无法替换的发起、等待余量暂沿用 950 的合并样本。无拆行时完全跳过归并。[公开实现及返回的分项](../../src/operator_model/operators/attention/flash_sparse.py) · [定价参数](../../src/operator_model/data/parameters/flash_qsli.json)

## 1Mi 单行回放

DT 合并轮的输入 entry 数依次为 3,584、4,096、4,096、4,096、2,560，总计 18,432。新价格中的归并输入 DMA、选取/映射、输出 DMA、屏障分项为 2,523.37、8,301.40、950.00、1,129.00 周期，合计 7.82 µs。PR 少一个归并轮，合计 6.51 µs。首发留空及关键团队的成本还决定整个 kernel 窗口。

| 设备 | 旧预测 µs | 新预测 µs | CA µs | 旧误差 → 新误差 |
|---|---:|---:|---:|---:|
| 950DT | 11.390 | 18.107 | 21.630 | −47.34% → −16.29% |
| 950PR | 12.988 | 18.997 | 21.092 | −38.42% → −9.93% |

六个开发窗的 WAPE 按 DT/PR 分别从 40.34% / 36.30% 降为 10.21% / 8.21%。长单行的 DT/PR 快慢仍判反。两个 SKU 的首波 MMAD 发起、从局部列表到归并的等待以及实际 DMA 回应均有波动。小窗可证实指令边界与关键归并团队，但无法单独校准这些差异随芯片、并发度和页分布的变化。此次开发只读取已有 trace，新独立计时另报。[开发回放六窗及单次查询成本](v112_merge_replay.json)
