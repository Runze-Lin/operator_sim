# QSLI 长上下文留出验证

这两次采集调用 A5 发布包的同一 `QuantSparseLightningIndexer` AOT，使用 B=1、H=32、D=128、每行 2048 个八位置候选块、TopK=512、1Mi 逻辑缓存、PA128 和 8201 列物理页表。Q/K 为原生 E2M1，分组 scale 为 E8M0，头权重为 FP32。CA 计时涵盖融合核 1 次调度的全物理指令窗。AI CPU metadata 使用同一 wheel 的宿主参考算法逐字生成，输入量化和输出时间序排序由调用方完成。

实际 PR 比 DT 快 1.423 倍。PR 的同核发起间隔更短，首次至末次 MMAD 的跨度缩短 24.795 µs；归并等尾部工作反而增加约 2.077 µs。两端的读操作数和去重后的候选地址量完全一致。现有观测同时改变了硬件和分核，无法独立识别缓存命中率、每次 HBM 服务耗时或哪个变化单独造成了这 24.795 µs。v1.12 在 PR 上预测 93.039 µs，高估 56.19%；v1.11 预测 87.557 µs，高估 46.99%。[DT 阶段](v112_wave_timeline_dt32.json) · [PR 阶段](v112_wave_timeline_pr32.json)

## 950DT 逐行更换候选页的 64 行

该样本同时改变 query 数、物理缓存背板和逐行候选地址。此前的 Q32 使用 257 个物理页，32 行共用同一组 256 个候选页；本次 Q64 为 8192 个有效逻辑页逐页分配独立物理页，folded K 背板共 68 MiB。每行从 128 个公共页及 128 个滑动候选页中各取 8 个块，每块含 8 个 token。8192 页中的 2176 页在本批被选中。[数据生成器](v112_wave_probe.py) · [冻结输入及逐行统计](v112_wave_dt_fixture.json)

原厂调度器把连续两行分给同一个团队，32 个团队各执行 64 个 tile。同一团队的两行实际重合 208/256 个源页和 1664/2048 个八位置块；相隔 32 行的页交集为 128/256。每行单独验证截止位置、FP4 解码和分组 scale、带权头得分、因果边界以及最终 512 个索引。对每行的未来候选故意赋更高分，以检验掩码是否生效。全部 32,768 个索引与 CPU 结果相同。[逐团队交集与地址摘要](v112_wave_addresses.json)

在 Q64 的**同一次采集**内还能看到真实的行交接。每个团队第 32 条 MMAD 是第一行的末条，第 33 条是第二行的首条；两次发起相距最小 5096、中位 5507.5、最大 6214 周期。交接中位 3.338 µs，比该样本全部相邻发起的中位 0.785 µs 更长。团队第一行和第二行各自首发至末退休的中位为 32.771 和 25.362 µs，说明把一行的实测窗口直接乘二，会丢失行间节奏的差别。

Q64 的 96 个核全部退休，最后一个为 `core19.veccore0`。逐核的 2048 条原生 `MMAD_MX` 均为 E2M1×E2M1→FP32 的 (32,512,128)，32 个实发团队的候选读取地址和重复次数逐一吻合。两次冻结预测 v1.11 和 v1.12 同为 146.5183 µs，分别高估 82.84%。本例的同核典型发起间隔不到旧例的一半，首次至最后一次 MMAD 的全局跨度因此从 69.108 缩短至 66.261 µs。Q、地址分布和物理背板同时变化，两段设备窗之差无法分离第二波的边际代价，也无法据此量出 HBM 命中率。离线 CA 从启动到 golden 为 1158.13 秒，随后解析导出 312.01 秒，共 1470.14 秒，单次调用正常退出。[正式收据](v112_wave_dt.json) · [Q64 阶段](v112_wave_timeline_dt64.json)

## 地址证据与核验

每行每个有效源块读取 544 字节，即 8 个 64B 键和 32B scales。离线解析每个 AIV 的 `MOV_SRC_TO_DST_ALIGNv2`，保留 GM→UB、单 burst 长度 544B 的指令，将双 burst 的源码地址和字节步长还原成两个独立地址。按物理 AIC 所配两个 AIV 汇总读取的带重复地址集合，与原厂 metadata 导出的逻辑团队逐一比对。PR 中部分团队读取了完全相同的一组源块，收据对此保留所有符合证据的逻辑 ID。GM 读指令的操作数字节与跨 HBM 总线实际传输是两个可以分别测量的量；本采集没有缓存 miss 计数。[期望地址与片内重叠](v112_wave_addresses.json) · [核验程序](v112_wave_report.py)

## 复现

`$PYTHON` 指包含 PyTorch、torch-npu 的 aarch64 Python 3.12 环境解释器。`$PACKAGES` 包含官方固定的 cannbotdsl、cannbot-arena-net-ops。`$ARENA_WHEEL` 为同一原始 arena wheel。启用本地 Unix socket IPC。每种情况只运行一个真实融合核，仅申请 PipeUtilization 和指令回调；原始文件保存在 git 忽略的目录中。

```sh
python -m calibration.candidate_indexer.v112_wave_capture pr --raw runs/new-wave/pr \
  --packages "$PACKAGES" --python "$PYTHON"
python -m calibration.candidate_indexer.v112_wave_capture dt --raw runs/new-wave/dt \
  --packages "$PACKAGES" --python "$PYTHON"
python -m calibration.candidate_indexer.v112_wave_report runs/new-wave/pr \
  --wheel "$ARENA_WHEEL" --out /tmp/checked-wave-pr.json
python -m calibration.candidate_indexer.v112_wave_report runs/new-wave/dt \
  --wheel "$ARENA_WHEEL" --out /tmp/checked-wave-dt.json
```

本次 PR 最外层计时进程收到 TERM 时，CA 和 msOpProf 保持运行，后续监控复用同一进程与日志。模拟器的原始返回码标为未知，数值、设备整窗、导出完成标志、每核 `END`、AOT 设备 ELF 与黄金集合全部独立核验。该端墙钟取自原始日志创建至最后写入，起点精度为秒。[接续监控](v112_wave_monitor.py)
