# Flash QSLI 多团队发起与行间交接

应用于 DeepSeek-V4.1-Flash 的候选消费者，MXFP4 Q/K、32 heads、D=128、Top512。在算子循环中，一个 tile 从 64 个候选块读取 512 个键，由两个 AIV 搬运、一个 AIC 发出一条 MMAD。表宽超过 2,048 页时，源码逐个求物理地址。设备 ELF 和源文件指纹见[内核审计](source-audit.md)。这里复用 v1.12 及以前采集，三项多行设备窗均属于开发回放。

本文的参数表和开发回放记录 **1.13.0 第一次冻结**（提交 `ec9ad01`）。归档重放时，可将该提交的 `src` 以 `git archive ec9ad01 src` 导出到临时目录，再让 `PYTHONPATH` 优先指向导出的 `src` 并使用本目录的脚本和 trace。**当前 1.13.1 对续片的修正**见文末；旧 trace 和原冻结预测仍可复核。

## 从哪几段 trace 取值

每个物理 AIC 内，按时间排列同一 (32,512,128) 的 `MMAD_MX` 发起刻度。乘 1650 并取整得到 950 的芯片周期。原厂 metadata 决定每个 worker 在哪一行、哪个 tile 开始；PR 将部分行分成两段，使用先前对双 AIV 源地址多重集合的核对恢复逻辑分派。全部允许的逻辑匹配均产生相同的行内初始 tile 序号，提取脚本对此断言。先在每个物理核上求相邻发起间隔的算术均值，使停顿计入该核的总跨度，再对核取中位数。跨行发起对单列。[逐核统计及完整样本](v113_mechanism.json) · [复现脚本](v113_mechanism.py)

## 映射到新输入

设 O 为同请求内不同查询在同一候选序号上访问相同 folded record 的比例。分母为双方该序号均有效的行对/序号数。物理 record 的标识为物理页和页内 8-key 块偏移。在线 API 可传 `candidate_order_overlap`，范围 0–1。采集不到地址时取 0.5，让间隔位于两个布局情景的中点；这个值没有业务频率或缓存命中率的实测依据。

源 metadata 迭代分配连续工作流。当剩余 W 个整 tile 和 N 个团队时，当前团队取 W/N 按半 tile 向上舍入的个数。对每个团队的起始、中部和共同有效末步取样；各团队都以自身起点为逻辑步 0。每一步先按（请求，行内 tile 序号）分组。若共有 P 个团队，组大小为 g，匹配比例为各组 g(g−1) 的和除以 P(P−1)。对最多三个不同取样步取均值得 A，再用 p=A×O 表示可能同序的团队对份额。对饱和、等长的完整行，相位在重复行上保持不变。变长前缀和跨请求时 A 是三点近似；缺少真实发起顺序时，它也不能复原设备上所有并发访问。源码对不满 tile 使用较小调度权重，在线按整 tile 近似这一边界。[算子实现](../../src/operator_model/operators/attention/flash_sparse.py) · [含变长、多请求的调度测试](../../tests/test_flash_qsli.py)

| 周期参数 | 数值 | 原始来源、适用假设 |
|---|---:|---|
| 首片错序 / 同序间隔 | 1737.98 / 3645.97 | 上表两个 DT 首片阶段的核间中位。wheel 中 QsliVector0._gather_half_scalar（819–868 行）参与每步的 64 个记录，CA 给出包含地址生成、搬运、环槽等待的有效发起间隔 |
| 续片错序 / 同序代理 | 1343.61 / 2534.00 | 错序来自 DT Q64 第二行。完全同序的多行续片当时无独立观测，以 DT Q32 长首片最后 4 个间隔的逐核均值中位近似稳态，4 对应源码 staging depth |
| 同请求行交接 | 5334.75 | DT 与 PR 两个有跨行事件的旧窗，对各自的行交接中位数取等权均值。覆盖上一行本地选择、当前环槽收尾及下一行预取 |
| 首次控制开销 | 14536.34375 | 三窗首次 MMAD 偏移的中位为 17454 周期，扣除参考芯片资源模型的首 tile gather+publish+Cube read=2917.65625。该残量合并启动和未分离的控制等待 |

对每一步，首片间隔取 (1−p)×1737.98+p×3645.97 周期，续片间隔取 (1−p)×1343.61+p×2534 周期。两者均不能低于目标芯片的发布、连续 Cube 读、MMAD、FIX 和 Vector 服务约束。每个团队计数如下。

1. 首 tile 走初始 gather→publish→Cube 读→计算→FIX→向量；全窗只收一次首次控制。一次 gather 的两个 AIV 并行读取各 32 个 544B record，乘目标芯片每字节周期后再计标量寻址准备。
2. 在每个请求的首个行片段，实际 tile 数减一给出首片间隔数。之后每个同请求行片段的 tile 数减一给出续片间隔数。源码在上个片段排空后，通过 `prepare_addresses` 和 `gather` 借用最多四个槽预取下一行（wheel 中 `ops/quant_sparse_lightning_indexer_dsl.py` 第 61、1520–1554 行），随后进行本地 TopK。在前后两条 MMAD 发起间已有一次实测交接，交接费取 5334.75、下一次数据准备和最小选择服务三者的最大值。
3. 收尾时按最后片段长度计本地直方图选择；末片段需写 partial 时补足 v1.12 的单片排空窗口。遍历所有团队取最慢一条链，再计跨核最终归并、全芯片逻辑 I/O 与片上环带宽约束。`projection.stages_us` 给出可加和的当前窗口分解，`first_fragment_interval_cycles`、`carried_fragment_interval_cycles` 和 `same_document_handoff_cycles` 给出前三项的原始周期价。

例如 DT Q64，L=1Mi，table_pages=8201、C=2048，32 个团队各拥有两个完整 32-tile 行。错序输入使 A=1、O=0、p=0；每队执行 31×1737.98 个首片周期、1×5334.75 个跨行周期、31×1343.61 个续片周期，再加首次和最终片段的局部资源与选择开销。关键团队为 65.396 µs，首次控制为 8.810 µs，全窗 74.206 µs。相比原始 80.133 µs 的差距包括首片慢核、最末 AIV 排空及资源模型尾窗的差异。`projection` 的阶段边界属于模型预算，设备测得的首条至末条发起可用于核对，不应逐项等同。

Q=1 或仅一团队时，保持旧的片内发起/跨核 LD 归并。UB 页表路线与显式 `scalar_lookup_cycles` 走资源定价。对 970DT，先用配置求团队数、分派与带宽/算力地板，再按频率转换控制周期。控制实现相近、标量寻址及环结构延续均为外推假设。三份已知多行样本不足以分离缓存、内存 bank、在途请求和请求间去重的贡献；O 相同的页内排列也能产生不同耗时。0、0.5、1 表示指定的输入布局情景，其范围不具有覆盖所有输入的置信度。[冻结参数](../../src/operator_model/data/parameters/flash_qsli.json)

## 1.13.1 第二次冻结对续片的修正

固定同一 DT、物理缓存背板与 Q64 metadata，将第一行与第二行的同核 MMAD 发起分别统计。全部团队候选顺序一致时，两行的间隔中位数（先算每核均值，再取核间中位）分别为 2926.48 与 1314.40 周期；保持相同页集合、逐行轮换访问顺序时为 1537.76 与 1320.89 周期。第一行差 1388.72 周期，第二行仅差 6.49。第一次冻结以 DT Q32 冷行最后四个间隔 2534 周期代理第二行同序端点，已显著高于这里实际出现的 1314.40 周期。第二次冻结把这两个已披露的对照用于判断模型结构，与持续封存的其余布局分开登记。

当前的续片间隔等于 **旧 DT Q64 第二行的 1343.6129 周期**与**目标芯片的阶段服务下界**两者的较大值。下界由 publish、连续 Cube 读、MMAD、FIX 和 Vector 需求逐项换算得出。1343.6129 完全来自第一次冻结前的旧窗；两个新观测用于检验此前的斜率假设。首片继续用 p 在旧的 1737.98 与 3645.97 周期间插值。跨行仍计交接，跨请求重新填充，原有首次发起和跨团队归并照原有公式。三种芯片共享同一表达式。

源码最多为相同请求下一行加载四个 staging 槽，行末还会受 metadata 端点裁剪；下一片不足四个 tile 时只预取其有效槽。在模型中，只对完成交接后的**相邻 MMAD 发起**定价，单个 tile 的片段贡献零个这种间隔。完整第二行已有两类对照，短片段的单独启动、跨多于两行的长期稳态以及未来芯片上的继承仍有外推成分。[源码及原始阶段证据](v112_wave_calibration.md)
