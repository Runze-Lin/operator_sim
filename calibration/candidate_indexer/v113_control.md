# 固定输入形状，只改变 QSLI 候选页的对照

A5 950DT，`QuantSparseLightningIndexer` 原生 MXFP4 AOT，B1、Q64、H32、D128、KV 缓存 1,048,576、每行 2048 个八位置候选、TopK512、PA128、8201 列页表、压缩比 1、因果屏蔽。原厂宿主 metadata 在三组输入上逐字相同，32 个团队各做连续两行，每行 32 个 (32,512,128) `MMAD_MX` tile。每个逻辑页有独立物理背板，共 68 MiB。实际 CPU 输入的 SHA-256 和冻结参数可直接复核。[冻结价格与主机预算](v113_frozen.json) · [数据与独立黄金生成器](v113_control_probe.py)

| 候选页安排 | 每团队相邻行共享页 / 每行总页 | 全批页并集 | 同一候选序号下，两行访问同地址的比例 | 32 团队同序号访问的不同地址数（平均） |
|---|---:|---:|---:|---:|
| `shared`，各行同一组页、同一顺序 | 256/256 | 256 | 100% | 1.00 |
| `moving`，128 个公共页，另外 128 页在 2048 页池内每行前移 48 页 | 208/256 | 2176 | 50% | 16.50 |
| `rotated`，页组与 `shared` 相同，只轮换各行访问页的顺序 | 256/256 | 256 | 0.390625% | 31.87890625 |

比例取 64 行的全部 2016 个无序行对 × 2048 个候选序号。两轮各自的 32 个并发团队也得到相同的成对比例。`rotated` 的因果末页固定，其余 255 个页按每行 13 位轮换，三臂都采用相同的候选序号置换。每个页读取相同 8 个块，每块 544 B，故每臂请求 71,303,168 B。`shared`、`rotated` 去重后均为 1,114,112 B，`moving` 为 9,469,952 B。这些值计量指令读取的源操作数；由缓存承接的比例尚无 HBM 计数器测量。[shared](v113_control_shared_fixture.json) · [moving](v113_control_moving_fixture.json) · [rotated](v113_control_rotated_fixture.json)

三个探针使用相同的 Q、K、E8M0 scales、FP32 头权重、物理页表、主机 metadata 和页内块偏移。CPU 直接解码两头的 E2M1 数值和 MX scales，计算每个实际候选的 ReLU 加权得分，逐行屏蔽尚不可见的未来键并选取 Top512。三臂所有位置的得分序列与屏蔽序列分别具有相同 SHA；截止位不重分，未来有更高分的干扰值。`shared` 和 `rotated` 各行的正确输出集合相同，`moving` 按其候选集合另算 golden。每次 CA 需通过 32,768 个输出位置校验。

从实际指令核验顺序时，每个 AIC 绑定的 AIV0 读取每 tile 的候选 0–31，AIV1 读取 32–63。解码每个 MTE2 `MOV_SRC_TO_DST_ALIGNv2` 的 OUT→UB 源地址与 burst 间距，按发起时间排序后与独立的 64 份有序地址 SHA 匹配。`shared` 与 `rotated` 的地址多重集合相同，此处的顺序校验可区分二者。[期望地址顺序](v113_control_order.json) · [收据程序](v113_control_report.py)

设备时间逐核核对实发 MX 指令、官方核窗与 `END`，以 96 核最早事件至最后退休为整窗。收据也计算实际发起在同一时间区间、且源地址相同的跨团队请求比例。区间宽度取 128、512、2048 周期，均以最早设备指令为零点。逻辑同序号特征不要求硬件在同一周期发起。时间分箱受流水相位、描述符合并和区间边界影响，应作为诊断项。

这组试验只有一个张量形状、三种布局，每臂采集一次。`shared` 对 `rotated` 固定各行完整页集、输出和总/去重字节，可检验页访问顺序的影响。`moving` 同时改变页集并集和部分地址顺序，适合用作中间布局留出；其计时差不能单独分摊给两个因素。三臂均使用同一台主机的独立模拟器进程，资格限于本 AOT、本设备配置和这组三种排布。

两个端点保持所有页集与数据相同，改变访问顺序后，设备整窗缩短 **26.817 µs**。该差值主要出现在第一行，团队窗中位缩短 26.091 µs，第二行各臂的中位都在 24.8–25.4 µs。两个端点同时发起同址读取的比例也有明显差别。CANN 发布源码的 `_copy_pa_pair` 在第二次读的地址比第一次至少大 544B 且字节间距减 544 不超过 39 位无符号整数上限时，会把两个块合成一个描述符。三臂实发的单/双 burst 计数都精确吻合该条件，端点之间每候选记录描述符数仅相差 0.15%。在本 AOT 和本组输入上，地址顺序确实影响设备窗；测量仍不能区分缓存 bank、端口队列或 HBM miss 各自的贡献。[shared 物理收据](v113_control_shared.json) · [moving 物理收据](v113_control_moving.json) · [rotated 物理收据](v113_control_rotated.json)

## 复现

`$PYTHON` 是已安装 torch 和 torch-npu 的 aarch64 解释器，`$PACKAGES` 含本地发布版 arena 和 DSL 包，`$ARENA_WHEEL` 指其固定的原始 wheel。msOpProf 需要可用的本地 Unix socket。每个模拟器使用独立进程、目录和 CA 实例，设备逻辑时钟与宿主导出墙钟分别记录。

```bash
for arm in shared moving rotated; do
  bash scripts/cann-run.sh env PYTHONPATH="$PACKAGES" OMP_NUM_THREADS=1 \
    "$PYTHON" calibration/candidate_indexer/v113_control_probe.py "$arm" \
    --cpu-only "/tmp/$arm-fixture.json"
  python -m calibration.candidate_indexer.v113_control_capture "$arm" \
    --raw "runs/my-v113/$arm" --packages "$PACKAGES" --python "$PYTHON"
  python -m calibration.candidate_indexer.v113_control_report "runs/my-v113/$arm" \
    --wheel "$ARENA_WHEEL" --out "/tmp/$arm-receipt.json"
done
```
