# v0.11 同集验证

RMSNorm 和 mHC Post 各复用 33 个旧 shape 开发，采集前冻结参数、形状、调用顺序和两个版本的预测。下表采用未传 `resident_aiv` 的默认接口；普通组为少 token 宽通道组（T≤4、D≥2048）的补集。其他路线沿用各自独立样本。

| 算子 / 分组 | 独立 shape | v0.10 → v0.11 WAPE | v0.10 → v0.11 最大误差 |
|---|---:|---:|---:|
| RMSNorm 全部 | 10 | 107.46% → 37.93% | 427.63% → 109.52% |
| 少 token 宽通道 | 4 | 21.02% → 21.07% | 32.01% → 34.12% |
| 普通 | 6 | 138.33% → 43.96% | 427.63% → 109.52% |
| mHC Post 全部 | 10 | 21.73% → 19.25% | 34.58% → 56.03% |
| 少 token 宽通道 | 5 | 22.25% → 30.44% | 34.58% → 56.03% |
| 普通 | 5 | 21.25% → 8.86% | 32.66% → 21.63% |

- **RMSNorm** 将相邻 FP32 统计量的并发写回与主输出字节分开计价。开发点 `[34,1536]` 的 MTE3 误差从 −1.659 缩小到 −0.581 µs。新点 `[33,1536]`、`[38,1536]` 整例误差降到 −20.0%、−6.4%。`[512,4096]` 仍高估 109.52%，主要来自写回与 SIMD 的重叠。固定耗时基线的同集 WAPE 为 30.31%。[方法](rms/method.md) · [诊断](rms/diagnosis.md)
- **mHC Post** 按切分路线选择三种启动状态的加权中位数。小宽组中三次已有核覆盖的调用 WAPE 从 28.52% 降到 4.76%，首次与扩核两次则出现大幅低估。五例提供前序覆盖数后的 WAPE 为 6.37%。另行做的按进程交叉检查未发现能稳定改善所有状态的默认估计。[方法](post/method.md) · [诊断](post/diagnosis.md) · [事后敏感性](post/context-sensitivity.md)
- **大数据量** 的最大完整主输出分别从 0.492/0.250 MiB 扩大到 4/2 MiB。RMSNorm 在同宽 1–4 MiB 区间未见稳定线性；Post 在同宽、同预热的 1–2 MiB 区间近似固定时间加线性增量。该趋势未用于回调冻结模型。[固定宽度实验与图](scaling/summary.md)
- **采集与交付** 共 26 次发射，获得 20 个独立 shape 的完整计时。Post 三条原始计时不合格，各用一次隔离重采与一次不计入样本数的预热补齐。RMSNorm 和 Post 的进程墙钟之和分别为 264.39、536.45 秒，两族合计 13.35 worker 分钟，包含无效采集与预热。DB 总量约 1.45 GiB；仅紧凑证据入库。对 950DT CA 的误差与 A7/A8、真实硬件和混合流应用的精度应分别验证。[采集审计](scaling/trace-audit.csv)

在不依赖 CANN 的干净环境安装 wheel 后，两个算子的 20 个 shape 各测试默认和显式上下文，共 1000 次调用。RMSNorm 单次最大 1.086 ms，Post 为 0.646 ms，包含各自首次加载参数；包导入另耗 24.27 ms。全路线在开发与独立样本上的统一查询墙钟见[完整总表](error-analysis.md)。[独立安装测试](wheel-check.json)
