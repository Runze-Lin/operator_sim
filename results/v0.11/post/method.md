# mHC Post 的 950DT 临界核模型

每个 token 的四路输入向量由一个 4×4 残差矩阵重新混合，再加入另一条残差输入的加权贡献。模型覆盖 CANN 9.2.1 的 BF16、N=4、带残差矩阵实现，T∈[1,256]，D≤8192 且为 16 的倍数。预测量是安装包内 `aclnnMhcPost` 发射的单 kernel 跨活跃 AIV 首末指令时间差（µs）。库身份属于 ops-transformer，CA 名称来自对应 DB。CPU 发射、排队和主机同步时间由系统层计入。

### 分核与阶段

T 是本卡 token 数，D 是向量宽度，N 是混合路数。在 T<32 的样本上观察到 `entry_kernel_5`；每个 token 起始分成 J=1 片，只要 ⌈D/J⌉>256 且 TJ≤32 就令 J 翻倍。逐 token 分支 T≥32 时 J=1，开发集对应 `entry_kernel_6`。令 W=⌈T/64⌉ 为最忙核的行数，A=J⌈T/W⌉ 为预测参与计算的 AIV 数，d=⌈D/J⌉ 为每片最大通道数。这里的 64 是本 950DT 配置的可用 AIV 数。D 较大时由更多核切通道，最慢一核的向量长度与总张量大小可以有不同的增长率。

对状态 z 和阶段 q 预测可见时间

```text
t(q,z) = b(q,z) + s(q) X(q) + e(q) (W−1)
L(z)   = Σq t(q,z)
```

b 表示该阶段固定暴露的 µs。SIMD 的 X=W⌈d/64⌉N(N+1)，表示每核 64 列为一组的局部混合工作，s 是每组工作的可见 µs。逐 token 分支 MTE2 的 X=2WNd/1024（KiB），使用本地 BF16 主张量读取量作为搬运负载代理，s 是每 KiB 的可见 µs。该代理不含所有辅助输入、重读、对齐和片上缓存；它的倒数不能认作 DRAM 实际带宽。逐 token 分支的 SCALAR 和 MTE3 对每多一行分别增加 e=0.04540、0.18884 µs。其余工作斜率置零，MTE3 与 other 使用状态共享的截距。以非负、soft-L1 损失（尺度 0.1 µs）拟合各阶段的 33 个开发时序，按分支独立估参。逐 token 分支旧样本最多两行，超过两行用同一斜率外推再独立检查。[完整校准系数](profile.json)

六个阶段为 arrival、SCALAR、MTE2、SIMD、MTE3、other。arrival 是全部核第一条指令到最晚结束核起点的时间。对该核把重叠指令区间按 SIMD、MTE3、MTE2、SCALAR 的优先级分配给单一阶段，未覆盖区间为 other。这样相加回到实测关键路径。阶段拟合依据可见时间，均匀分摊重叠区间或直接把队列 busy 时间相加会给出其他系数。

### 默认时延与可选的前序 AIV 覆盖

若系统模拟器提供 `resident_aiv`，记它为 H，即此前同类调用的核覆盖高水位。H=0 表示首次，0<H<A 表示扩展，H≥A 表示复用，然后取相应 L(z)。这个条件变量是执行顺序的代理，不能据此判定特定缓存命中。若缺失 H，用 tiling 分成三组，统计开发时序中三种可观测状态的频数。按 L(z) 从小到大排序，返回累积频数首次达到总数一半的状态。这个加权中位数在该经验状态分布下最小化绝对时长偏差，与固定样本集 WAPE 的分子相符。它不对调用顺序做后台跟踪。三种状态的时延也在低层模型的 `context_predictions_us` 一并给出，供首用敏感场景分析；三种数值不构成置信区间。

| 部署分组 | 首次 | 扩展 | 复用 |
|---|---:|---:|---:|
| 少 token，切通道 J>1 | 1 | 5 | 8 |
| 少 token，整通道 J=1 | 4 | 2 | 2 |
| 逐 token | 1 | 2 | 8 |

这些频数来自旧开发批的执行顺序。CA 的首次调用、核扩展与后续复用各有不同开销；系统仿真如果几乎每次都创建新流，默认值的误差可能上升。模型没有识别真实缓存内容或两次算子之间的跨流干扰。复用旧版同形对照 [2,4,6144]，首用 4.84 µs、批尾 2.90 µs，关键核均为 1578 条 SCALAR 与 5 条 MTE2。进一步的阶段差异涉及 MTE2、SIMD 和到达时刻，仅凭这个对照无法分离具体硬件状态。把旧 10 个冻结样本收入开发集后，不再沿用它们的独立标签。[旧同形对照](../../v0.10/wide/paired-controls.json)

### 可复核算例

[3,4,4352] 沿通道切 J=16，A=48，W=1，d=272。向量工作为 ⌈272/64⌉×4×5=100。在切通道组 14 条记录中，8 条对应复用；默认返回复用值 2.325 µs，显式 H=0 的首用值 4.749 µs。两个预测都在新 CA 前冻结。对逐 token [256,4,1024]，W=4、A=64、J=1、向量工作为 1280，主输入代理为 32 KiB；在 T=64 已覆盖的单流中，默认及已知历史均估 4.837 µs。更大输入的测量与相邻增量见独立误差报告。[冻结的算例与参数](freeze.json)

### 适用边界与复核来源

该方法分开确定逻辑工作、切片和关键阶段，再由目标硬件的搬运与事件时序校准队列成本。这里的 64 核、256 列分片阈值、两条库入口、状态分布、阶段截距和斜率均属于当前 950DT 安装与覆盖的开发样本。A7/A8 的分核、实现选择、频率、存储成本和状态分布需要目标平台证据，当前没有跨代独立验证。已加载参数的求值只对三个状态各求六次阶段时间，无需运行 CA 或访问历史 trace。

CANNBot 的 950 数据搬运机制卡用于核对单次搬运组织、对齐和缓存可能改变 MTE 时间这一解释边界。原始 trace 的 exposed time 和逻辑字节尚不足以测出峰值利用率或缓存命中率。知识库指纹 75ef3269042fe870de858b72c10d67eb58713d0485d0c0f8e4f08a95fa146b8f，卡片为 stable、trust tier unverified。[机制卡的固定版本来源](https://gitcode.com/cann/asc-tools/blob/14714fdab5b495b048e13151b418f058cc66c9ce/skills/tool-ops-tune/ops-mechanism/references/optimize/data-copy.md)
