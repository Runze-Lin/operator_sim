# RMSNorm 写回诊断

从开发集 33 份完整数据库提取了每个核的写地址、搬运字节、开始和结束 tick，再定位整次发射最后完成的核。每个核的 MTE3 队列均有两条实际 `MOV_SRC_TO_DST_ALIGNv2` 写回和一条寄存器设置。两条写回分别产生归一化输出和逐行 FP32 统计量。

**已确认。** [34,1536] 的临界核 AIV1/7 上，4 B 写的时间区间为 [28588,32542)，3072 B 写为 [28712,32544)，二者交叠 3830 ticks。在 1.65 GHz 下，同核两次搬运的原始时长相加是 4.719 µs，按暴露口径 MTE3 仅占 2.325 µs。全芯片 34 个统计量写集中到相邻的 FP32 地址，其中 32 个位于一个按 128 B 对齐的窗口。核间统计量写耗时范围 125–3998 ticks。旧模型仅按总数据量和多行附加开销估算，未描述并发小写回。在该点，MTE3 低估 1.659 µs，占总低估 2.213 µs 的 75%。

**机制假设及余差。** 实际重叠、相邻地址和长尾时延来自 trace；在缺少仲裁、cache 事务与 bank 计数器的情况下，无法区分同区间写合并、仲裁和同步发起时序各自的因果贡献。模型借相邻写者近似 MTE3 暴露，对该开发点的 MTE3 低估降至 0.581 µs，总低估降至 1.135 µs。arrival、SCALAR 分别仍低估 0.271 和 0.275 µs。小 token 时未知驻留状态继续影响总时延；使用新 shape 的真实上下文只能作为额外诊断，默认精度仍按 shape-only 计算。

## 冻结后验证与固定宽度放大

十个新形状的默认 WAPE 从 107.46% 降到 37.93%，最大误差从 427.63% 降到 109.52%。少 token 宽通道四个点的 WAPE 从 21.02% 变为 21.07%；其余六个从 138.33% 降到 43.96%。两个相邻形状 [33,1536] 和 [38,1536] 上，写回预测 1.740/1.760 µs，CA 为 2.233/1.976 µs。整算子旧误差 −39.6%/−27.5%，新误差 −20.0%/−6.4%。

较大数据量依然高估。本次固定 D=4096 的最大输入为 2,097,152 个 BF16 元素，上次开发最大量是 258,048 个，扩大约 8.1 倍。下表是同一进程内的独立测量，四点均用满 64 核。并集是临界核上至少一条 MTE3 指令在途的 tick，可去除同队列指令的重复计时；再扣除被 SIMD 占用的区间即可还原暴露 MTE3。

首个点为首次启动，在判断规模趋势时应单列。后三个已驻留点每次翻倍后的时间倍率为 0.94×、1.35×，尚不能给出稳定线性斜率。临界核 SIMD 独占时间依次为 0.60、1.03、2.04 µs，随每核行数增长；写回耗时则受发起时序和重叠影响。从 256 行到 512 行，临界核从一对写回变成两对，其 BF16 写分别处理 7 行和 1 行；同时，SIMD 掩盖了 1057/2230 的写回 tick。用开发集估计的共享字节成本投向最后一个点会过高估算暴露写回。固定耗时对照（开发集耗时中位数）在这十个点 WAPE 为 30.31%，原因是实测 1.98–6.46 µs 仍较集中，机制模型却随输出量扩大到 10.16 µs。当前的多行分片及写回重叠建模仍缺少足够独立证据。

两个批次共 10 次 CA 发射，执行墙钟分别为 84.1 和 180.3 秒，数据库合计 445.0 MiB。十个 shape 的两个输出都通过 CPU golden，临界核数据库完整，实际 kernel 均为 `entry_kernel_1388`。每个 shape 在已加载进程内连续计算 100 次，预测中位 25.85 µs、最大 37.8 µs。该数字计入每次重新计算 shape，不计 Python 启动和首次载入 profile。
