# 950PR 的 B11 索引器：能验证的分块和未导出的写回

`[99,64,7168]` 的 **CA 官方设备窗为 6.888 µs**，公开资源模型为 **6.461 µs（−6.20%）**。数值、计时、指令三种资格要分开：输出缓冲区预填 BF16 NaN，运行后 6,336 个元素全部与正确值相符；所有 28 AIC 和 56 AIV 都有物理 `END`，逐核首发和末次可见退休与官方时间表相符。下面的验证发现已保存的指令导出没有记全结果写回，因此 **6.888 µs 是供应商报告的设备窗，不能从该 trace 独立证明每个未出现的 MTE3 何时退休**。

| 独立核验 | 950DT | 950PR |
|---|---:|---:|
| 金标准通过 / 应查元素 | 6,336 / 6,336 | 6,336 / 6,336 |
| 有效输出矩形 × K 分段数 | 1 × 32 | 1 × 28 |
| 按所有 A/B 初始地址还原的分片 | 32 次 K224，合计 7168 | 28 次 K256，合计 7168 |
| 从每个 AIC 重建的 MMAD | 32 条 `[99,64,128]` + 32 条 `[99,64,96]` | 56 条 `[99,64,128]` |
| 实际 FP32 部分和写入 / 读回 | 811,008 / 811,008 B | 709,632 / 709,632 B |
| 读部分和 / 有最终写回记录的 AIV | 50 / 50 | 50 / 34 |
| 实际导出写回 / 应输出字节 | 12,672 / 12,672 B | 8,576 / 12,672 B |

**为什么先前的几何核查失败？** 原核查先验证 Cube 的真实 A/B 起址、各矩形在整个输出平面无重叠地覆盖、各矩形对整个 K 无缺口的分段、每条 `MMAD` 尺寸，再验证 AIV 的最终输出写回是否连续。PR 在最后这一步失败。把二者单独验证后，Cube 所有检查均通过；完整写回资格仍然不通过，原失败回执保留。每个芯片均独立从该次实际 A/B 加载地址和 MMAD 重建；没有把 DT 核号套给 PR。

**缺口在什么位置？** 16 个读了完整部分和的 AIV 未导出最终写回；共差 `16×256=4096 B`。按 BF16 输出起点取相对地址，六段缺口为 `[1024,1280)`、`[5376,5632)`、`[7680,8192)`、`[8704,10496)`、`[10752,11520)`、`[11776,12288)`。这 16 个核最后可见指令为 9 个 `SET_FLAG`、5 个 `VF`、1 个 `RV_PLT` 和 1 个 `RV_VLD`。其余 34 个核写入的地址和 burst 长度均已验证。

**排除了哪些解析问题？** 对全部逐核 JSON 和整片 JSON 搜索所有具有 `src_mem=UB, dst_mem=OUT` 的指令名称；按 burst 展开后两视图逐核一致。核对二进制可视化文件：时间线和 JSON 字节一致；该文件另外的逐 PC 计数表以及所有核的 `instr_exe.csv`，也只在同样的 34 个核记下最终写回 PC `0x9000daf674`。因此数值差异不是本工具漏识别某个 `MOV`、未展开 stride、选错核或时钟零点。此轮低开销采集没有保留更底层的逐周期流水 dump，不能确定 CA 生成导出时删去指令的具体环节，不能把未出现的 16 个描述符补入实测。

这次实测 PR/DT 为 **0.9762**；两端新模型各自计价给出 **0.9979**，比值高估 **2.22%**。旧模型和直接拿 DT 延迟都预测 1.0000。这一形状支持 Cube 的切 K 机制和部分和流量；对 PR 末端流水的判断应保留上述限制。
