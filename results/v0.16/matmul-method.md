# MatMulV3：从目标资源独立计算 BF16 稠密 GEMM

输入 `[M,N,K]` 和目标芯片配置后，[模型](../../operator_model/matmul_resource.py)直接输出时延、活跃核和各阶段耗时；同一组资源换成任意芯片名，结果相同。计算中既不读取另一颗芯片的总预测，也不加载 SKU 配对时间、按形状查表或以总时延回归。适用对象为已支持的安装包 `aclnnMatmul → MatMulV3`、BF16、无转置的连续 ND 格式、无 bias。对未来芯片的假设是库仍使用类似的分块、DMA 和 MMAD 指令；算法或指令选择改变时仅是情景预测。

**第一步，得到工作。** 依照已实现的库分块抽象，以目标核数、L1/L0A/B/C 容量和目标算存比搜索块，得到最大输出块 `m×n`、MMAD 的 K 深度 `k₀`、每轮搬运的 L1 页深 `p`。块网格 `gₘ=ceil(M/m), gₙ=ceil(N/n)`，共有 `J=gₘgₙ` 个 job，每个对应一个输出块；每波并发 `a≤目标 AIC 数`，末波可少于此前各波。不按 SKU 选择算法或参数。数学工作为 `2MNK` ops，单条 MMAD 的物理占槽工作估计为 `F(z)=2 align16(m) align16(n) align16(z)`；其中 `z` 为实际片深（末片可能不足），`align16` 向上补齐到 16 个元素。一条 MMAD 的数学工作、占用阵列槽数和搬入字节量三者不相同。

**第二步，算每一级的数据量。** 每单位 K 深在 L2→L1 需搬运 `r=2(M gₙ+N gₘ)` 字节：每个 BF16 元素 2 字节，A 沿 N 块重复、B 沿 M 块重复。HBM 冷载时去重后仅需 `u=2(M+N)` 字节；假设本页唯一输入字节 `u·p`（最后不足一页时按实际长度）能放进目标 L2，则全页按冷载去重，否则按 `r`。这是**缓存命中场景假设**，不是 cache miss 的 CA 计数器。用 `b=a/J` 分摊该波引起的共享流量，再乘实际深度。L1→L0 的总操作数字节暂假设与 L2→L1 相同（不计二次重载）；全局输出写回 `2MN` 字节。每核 MTE2/MTE1 关键描述符取 A、B 中较大的一个；二者近同时发起，避免把重叠的持续时间相加。只建数据路径，不把整片 HBM 带宽自动乘到发指令的开销上。

**第三步，按周期调度。** 以下带宽均为 bytes/cycle：`β₂, β₁, βw` 为每核的 MTE2、MTE1、写回；`βL, βH` 是整个芯片的 L2 和 HBM。给定频率 `f` GHz，GB/s 除以 `f` 即可转换。Cube 单核能力 `π=1000·P/(Ncore·f)` ops/cycle，其中 `P` 是整芯片 BF16 TFLOP/s；缺失时继承 DT 配置推得的单核 ops/cycle。关键公式为：

| 时间（周期） | 如何算及如何理解 |
|---|---|
| 发起 | `H₀+h log₂(aₘₐₓ)`，每次调度只付一次。H₀ 是单核首条到发首对 DMA 的固定指令/启动窗口，h 是跨核到达斜率，aₘₐₓ 是最忙波的并行核数。 |
| 每页首对读 | `Lr + D(d)`，其中 `D(d)=max(2d max(m,n)/β₂, r d b/βL, u' d b/βH)`。d 为页深，u' 为上文缓存场景的 u 或 r。一次请求先付读延迟 Lr；三层争用取慢者，不重复累计。 |
| 转入 L0 | `L₀ + B(z)`，`B(z)=2z max(m,n)/β₁`，z 为首片深。L₀ 表示首对读取完成到依赖 MMAD 可启动之间未归因于字节流的开销。 |
| 页内 Cube | 若有 nfrag 片，首/常规片深 z、末片深 t，则 `C(d)=(nfrag−1)max(Ic+F(z)/π, B(z)) + Lc+F(t)/π`。Ic 和 Lc 分别是去除按峰值计算项之后的连续 MMAD 发起间隔与单指令首延迟，绝不能把它们都乘指令数。 |
| 多页稳态 | `II=max(2Ir,D(d),(Lr+D(d))/2,C(d))`。两个输入描述符、MTE/共享带宽、双缓冲最多两页并行，以及 Cube 是四个不同的约束；Ir 是 A/B 描述符间隔，作为发起端下限使用。d 取首页深。 |
| 每波尾段 | `E=Lw+max(2mn/βw,2MN b/βL,2MN b/βH)`。只计最后一条 MMAD 到结束的暴露尾段，不重复收费整个提前入队的 FIXP。 |

每一波串接 `首对读 + 转入L0 + (页数−1)II + 末页Cube + 尾段`。输出块波之间保守串行并共用全局发起开销，满波成本乘波数，最后不足一波独立定价。不枚举每条指令、每页或每个 job；合计周期除以 `1000 f` 得设备微秒。大 shape 若切入 split-K、全载、不同流水深度或调度重切，本规则未经过验证。

**校准证据。** [导出脚本](../../development/validation/sku16/matmul_dt_calibrate.py)仅枚举 v0.2 的 DT 捕获清单与 `runs/v8cube/matmul_*` 的成功 DT 记录，对照 SoC、原始 trace 或 DB 的 SHA 后提取。17 个不同旧 DT shape：10 份 msOpProf，7 份 npusim。逐个选取尾核；对首对读、L0 提前量、最后 MMAD 后的写回分别按该步的字节量解非负直线，截距是周期，斜率倒数是有效 bytes/cycle；首发 / 到达按核数对数校准，MMAD 首延迟和 II 取扣去对齐 ops/π 后的中位数。总实测时间只在参数冻结后的回放中使用；不作为任何参数的拟合因变量。[参数](matmul.json)与[来源清单、原始阶段观察和 SHA](matmul-dt-provenance.json)均可重建。DT-only 开发回放 WAPE **4.08%**，最大 **10.88%**（`[1,256,1024]`）；17 个开发样本不可视为独立验收。

| 参数 | DT 来源/默认值 | 配置覆盖（可选） |
|---|---|---|
| H₀、h | 3381.3 cycles；91.25 cycles/核数翻倍 | `matmul_launch_cycles` 修改 H₀；h 暂继承 |
| Lr、Ir、β₂ | 1173.5、15 cycles，47.15 B/cycle；Ir 指两条输入描述符之间，不是整页 completion 的 II | `matmul_read_latency_cycles`, `matmul_read_ii_cycles`, `mte2_bandwidth_gbs` |
| L₀、β₁ | 33.69 cycles、180.65 B/cycle | `matmul_l0_latency_cycles`, `mte1_bandwidth_gbs` |
| Lc、Ic | 99.92、97.92 cycles；按平均有效成本继承，不等同单元硬性流水深度 | `matmul_mmad_latency_cycles`, `matmul_mmad_ii_cycles` |
| Lw、βw | 381.81 cycles、158.30 B/cycle；βw 是暴露写回代理，不是独立测得的 HBM 吞吐 | `matmul_drain_cycles`, `mte3_bandwidth_gbs` |
| βL、βH | L2 缺省沿用 100 B/核/周期的库调度提示；HBM 来自目标必填配置。没有单独的命中率、争用或 DRAM 首延迟校准 | `l2_bandwidth_gbs`（片级），`hbm_bandwidth_gbs`（片级） |

**算例。** 对 DT `[256,512,256]`，目标分块 `[64,64,256]`，32 核各执行一次 MMAD。数学工作 67,108,864 ops；按页可容纳的情景，冷 HBM 读 393,216 B，而 L2→L1 重复读 2,097,152 B，输出写 262,144 B。发起 2.326、首读 1.132、转 L0 0.130、MMAD 0.216、暴露写回 0.297 µs，计 **4.101 µs**；DT CA **4.192 µs**。这些是设备估计时间，不是计算该预测的主机时间。切换到未知芯片时只有资源和可选的发起/流水参数变化；不到物理板或独立模拟器验证之前不能把这些数字当未来芯片真值。

**冻结后发现的适用界限。** 在 PR 上，`[1024,2048,32]` 的 4 个尾部大块实际被拆给 24 核，部分尾块的 MMAD 已在第一批结束前开始。`[1536,2048,16]` 的 28 核、56 条 MMAD 则都预测正确，仍将两波估成 9.394 µs，而 CA 为 4.755 µs。当前按波重复计价首读和排空，无法还原跨波预取及提前入队的写回。后一项开销各占多少仍待识别。需要跨代外推多波薄 K 时，这两个实测误差是现有模型的已知边界。[逐点证据](sku/1536-multiwave.json)
