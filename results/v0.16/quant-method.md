# DynamicMXQuant 的目标资源模型

固定合同为 ops-nn 的 `aclnnDynamicMxQuant`，BF16 输入沿末轴每 32 个元素一组，输出 E4M3FN 数据和 E8M0 scale。目标单卡输入为行数 R、列数 C。第 3.1、3.2 节的行列分核和 UB 规则使用目标 AIV 总数和 UB 容量，给出实际分配核数 A、最忙核行列尺寸和本地 tile 的行列 h、w。实现假设来自 950 的 tail-axis 路线。

**每个 tile 要做多少工作。** 分组数为 `g=h⌈w/32⌉`，BF16 输入读 `x=2hw` B，数据和 scale 合计写 `y=hw+g` B。主向量循环和 scale 整理循环合计 `n=⌈g/8⌉+⌈g/128⌉` 轮。模型将每轮换成 DT 观测的等效工作 κ=3469.52 峰值操作单位，代表指令混合与占槽效率。该数不能解读为 3470 条 ISA 指令。尾块按实际 h、w 重算。

**按目标硬件计价。** 下式所有时长均为目标周期。f 为 GHz，P 为全芯片 16 位 Vector TOP/s，V 为全部 AIV 数，`p=1000P/(Vf)` 为每核每周期的峰值操作数。缺失 P 时使用 DT 每核每周期能力。令 `B=min(B_HBM,B_L2)/f` 为全片可用 B/cycle，未给 L2 吞吐时只使用已知的片外限额。以 `a=RC/(r_core c_core)` 个等效满载核估计共享带宽分摊，分母是最忙核行列尺寸。局部读、发起、写数据率分别为 bᵣ、bᵢ、b𝓌，均为单核 B/cycle。取局部与共享限额中较慢者。

| 每 tile 服务 | 公式与含义 |
|---|---|
| 读就绪延迟 | `L=L₀+x/min(bᵣ,B/a)`，L₀ 是描述符发起到首批数据就绪的固定部分。 |
| 读发起端占用 | `I=x/min(bᵢ,B/a)`，前一次数据仍在途时，端口可以发起下一块。 |
| 向量服务 | `S=H_v+H_dep+nκ/p`，H_v 是 VF 发射/固定指令与未分离的队列开销，H_dep 是输入就绪到发起 VF 的间隙。 |
| 输出服务 | `W=L𝓌+y/min(b𝓌,B/a)`，L𝓌 含数据和 scale 写回窗口固定部分。 |

**如何把服务合成时间。** 设 Uᵢ 为第 i 块读发起，Vᵢ 为向量结束，Eᵢ 为写结束，首块从周期 0 开始，尚不存在的前驱约束忽略。则
`Uᵢ=max(Uᵢ₋₁+Iᵢ₋₁,Vᵢ₋₂)`，
`Vᵢ=max(Uᵢ+Lᵢ,Vᵢ₋₁,Eᵢ₋₂)+Sᵢ`，
`Eᵢ=max(Vᵢ,Eᵢ₋₁)+Wᵢ`。
第三次预读要等第一块用完其输入槽，第三次计算也要等第一块输出写完。总耗时为
`[H₀+h₀ log₂A + max(E_last,(X+Y)/B) + H_end]/(1000f)` µs。
X、Y 为全张量的读写字节，按冷输入、输出均写至片外的情景给出共享总量下界。H₀ 是首次发数据读之前的启动周期，h₀ 是活跃核数每翻倍的额外到达周期，H_end 是最后写完成至 kernel 指令结束。一次 UB 直接闭式计算。多轮利用五个状态的最大加法递推，重复等尺寸块用矩阵快速幂，复杂度随轮数对数增长。

**参数来自什么测量。** 13 个旧 950DT shape 的逐阶段统计覆盖首读、两条写描述符、VF、单双 UB。重验原始 trace SHA-256、精确 SoC 和输出正确性；每个参数从对应事件边界提取。首读周期对 payload 的非负线性斜率给出 bᵣ，最快的后继描述符发起给出 bᵢ，较大写的最快观测给出 b𝓌，其余固定部分分别估计。H_v 与每轮增量用实际 VF 发起至第一条写发起区间获得。首次 VF 就绪间隙和末尾取中位数。读写速率含 CA 争用，重叠区段无法单凭这些样本唯一辨识物理端口或实际外存流量。[DT 参数与单位对应数值](quant.json) · [16 个 tile 的逐项证据](quant-dt-evidence.json) · [提取脚本](../../development/validation/sku16/quant_dt_calibrate.py)

| 细项 | DT 缺省值 | 目标配置覆盖 |
|---|---:|---|
| H₀、h₀、H_end | 4747、139.5、16 周期 | `quant_launch_cycles`、`quant_arrival_log2_cycles`、`quant_end_cycles` |
| L₀、L𝓌 | 972.5、336.4 周期 | `quant_read_latency_cycles`、`quant_write_latency_cycles` |
| H_v、H_dep | 850.5、5 周期 | `quant_vf_dispatch_cycles`、`quant_vf_dependency_cycles` |
| bᵣ、bᵢ、b𝓌 | 36.0、68.9、57.9 B/cycle/核 | `mte2_bandwidth_gbs` 同时覆盖读服务和读发起局部率，`mte3_bandwidth_gbs` 覆盖写。显式输入单位 GB/s/核。 |

**同 shape 换芯片的例子。** BF16 `[768,4096]` 的接口数据量相同，输入 6,291,456 B，输出 3,244,032 B。DT 分给 64 个 AIV，最忙核迭代两次，每块 6×4096；块内读取 49,152 B，向量循环 102 轮。PR 分给 56 个 AIV，最忙核两块、每块 55×512，分别为 56,320 B 和 117 轮。按目标配置，DT 的启动、UB 窗口、末尾分别为 3.384、3.901、0.010 µs，合计 7.295 µs；PR 对应 3.368、7.448、0.010 µs，合计 10.825 µs。以上是预测。小 shape `[1,128]` 只用一个 AIV，预测 DT/PR 均约 4.21 µs，主要是固定启动和首读。模型对共享带宽的竞争、冷数据占比及细粒度描述符固定成本很敏感。
