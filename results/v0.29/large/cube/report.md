## 几何、流水与资格

**MoE**。Pro 的一个输入批 B8×32Ki，经 top6、均衡 EP384，给单个目标专家贡献 8×32768×6/384=4096 行。本次将该批视为 EP 组内唯一独立来源，或取一份来源的局部贡献。若一个 EP 组实际合并 R 个相互独立、相同大小的 attention DP 来源，则目标行数为 4096R，真实 router 倾斜还会改变结果。仅凭“单卡 B8”不能唯一决定该 expert 的接收行数。例如 384 张卡组成 48 个独立 attention TP8 组并同时汇聚时，均衡预期为 196,608 行。384 专家、EP384 使每个 rank 持有一个专家，专家内 TP8 的本地中间维为 3072/8=384。该合同测稠密 MXFP8/E8M0、BF16 下投影及分组计数 [4096]，实际 Pro 配置中专家权重为 FP4，因此本例验证同几何的 MXFP8 库。假定输出粒度 16×128 时，上/下投影输出任务约 1536/14336 个，均摊 32 AIC 为 48/448 轮，28 AIC 为 55/512 轮。真实分核及 MMAD 指令见完成后的端点回执。GMM1 全量核对 1,572,864 个 E4M3 输出和 49,152 个 MX scale，GMM2 全量核对 29,360,128 个 BF16 输出。CPU 基准用有符号周期数据，缓存等值行、列的完整 K 维归约。6,720 项 CPU 标量全归约交叉核验逐位一致。真实 ACLNN 库执行全部数据。

**Recurrent**。Kimi 单卡 B128 普通 decode，TP8 将 96 个总头切为 12 个本地头。1,536 个独立状态链、每链 128×128 FP32，入口和出口状态分别 96 MiB。假定每活跃 AIV 接收一个链任务，DT/PR 各核最多 24/28 条。在线默认大形计时尚不支持。额外封存的情景按单链价格乘最大链数，并受冷状态 HBM 下界约束。它可对照真实多头新窗，未计链间重用及部分尾波。合格条件覆盖全部 BF16 attention 与 FP32 final state，KV 排列、显式外部 gate，不含服务侧的 VK 格式转换或分页汇集。本次 host 检验两组输出，未另作输入初态修改的逐值断言。

**Addmm**。Flash 的 indexer.wk 给出 B8×32Ki 的 262,144 行，宽度 K=512、N=128。本例显式加入 BF16 [128] bias，验证该 Addmm 合同，Flash 配置未证实有这一 bias 节点。当前价格按 [512,128,32] 粗分，DT、PR 的 512 个输出块分别约 16、19 波，原包分块可不同。全量核对 33,554,432 个 BF16 输出。CPU 参考将输入原有的 17 点周期精确求和。

**显式 FLA V2**。Kimi [1,1024,12,12,128,128] 分为 16 个序列块和 192 个块头任务。DT 的 Prepare/FwdH/Finalize 临界核依次 6/16/6 个块头，PR 为 7/16/7。该长度用公开 V2 host 强制进入三段，Kimi 默认规则会在此几何选 V1。四组原有金标同时检查 attention、Aqk、Akk、末状态及初态未变，要求实际绑定发行版 libcust_opapi、三个发布 .text 指纹与每个物理核 END。历史 [1,192,4,4,128,128] 双端完成，表中排队的是 token×head 数量增至 16 倍的新形。B1×32Ki 及更长单请求真正会选 V2，在本登记中另存形状投影，尚无对应合格 CA。按 192×4 的 DT 实测约 1.04 GiB 原始 trace 做量级估计，B1×32Ki、12 头可能超过 500 GiB/端，实际分支及排队会改变此数。

**官方融合 V1**。Kimi 默认小块 FLA packed 的实测重复 SET 和完整窗缺口仍在。状态/访存工作已有下界，整核时延保留 N/A。[V1 原始合格性](../../kda/report.md)

## 离线运行与复现

共享文件锁每次只允许一个新端点进入采集。MoE、Recurrent、Addmm、V2 每端墙钟/磁盘上限依次为 8 h/48 GiB、2 h/20 GiB、6 h/32 GiB、3 h/40 GiB，8 端均至多一次。每个端点在本目录写独立 JSON，原始 run.log、cost.json、官方表和逐核 trace 位于 runs/large29/cube/{op}-{dt,pr}/。任何未通过的端点会保留数值失败或完整性原因。3 个 V2 主阶段要求正式文本指纹，其他算子保留安装包 ELF SHA、实际 kernel 名、所有参与核的第一/最后时钟、物理 END 和指令指纹。[CPU 与设备验收源码](../../../../development/validation/large29/cube)
