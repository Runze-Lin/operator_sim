### 有排队请求时，每个物理数据拍搬了多少

以 1 µs 为一段，分别在每个内存通道上数 32 B 的读拍、写拍和 DFI 总拍。只取同时有读写、且至少 95% 周期队列非空的区段。B8 在 222,331 个区段上实收读 115,676,231 拍、写 58,910,073 拍，总计 222,331,000 个通道周期，有效占比为 78.5254%。B4 的 84,363 个合格区段独立重复了这一现象，占比为 78.6464%，相差 0.121 个百分点。B4 的结果能检验稳态带宽，无法检验整次启动、退出或全程耗时。[原始价格与单位](service.json)

950DT 控制器提供的物理引脚上限为 128 通道 × 32 B / 1 ns = 4.096 TB/s。芯片配置填写 4.000 TB/s，故冷流混合服务占配置额定带宽的比例为 η = 0.785254 × 4.096/4.000 = 0.804100。按目标配置再次计算，参考有效带宽是 3.2164 TB/s。950PR 和 970DT 复用这个无量纲比例是外推假设；控制器制式、访存交错和排队深度都会改变它。较少活动 AIV 无法堆满队列时，临界核搬运/计算服务另行约束。

### 从张量计算到设备耗时

令 R、W 表示单次输入和逻辑输出字节，L 表示总 L2 容量，V 为正在预取的最多两块输入在全部活动 AIV 上的字节。顺序单遍访问下，把剩余 L2 在已读数据和待回写的数据之间按占比分配，得到暂留比例 α = min(1, max(0,L−V)/(R−V+W))。初始阶段的等效只读预算为 αR；稳态混合预算为 (1−α)(R+W)。这是字节服务量分解，首个实际写指令可在等效初读阶段中出现。

设 B 是目标配置的字节/µs，S 是目标启动与收尾 µs，P 是现有模型的整窗 µs。片外流量服务下界为 min(P,S+αR/B) + (1−α)(R+W)/(ηB)。最终取该项、P、临界核 MTE2 / SIMD / MTE3 服务下界的最大值。各项可以重叠；资源跟芯片和实际核数重新计价。970DT 整批案例中，核内流水仍提供更大的时间下界，片外价格变化对最终点预测为零。

以 B8 为例，R=3,758,096,384 B，W=1,937,768,448 B。DT 64 AIV 各执行至多 820 轮；等效初读/混合阶段分别为 22.939 和 1731.942 µs。候选在同一个原生设备包络上从公开版 −32.52% 改至 −1.36%，旧的跨算子 Cast 带宽情景为 +4.98%。B8 已用于识别控制器效率，所以这项结果是开发回放。112 个已有小形完整指令窗使用同一公式，两个方法逐窗同值；DT WAPE/最大 4.74%/13.61%，PR 为 7.71%/16.83%。[逐形预测、误差、未缓存开销与待收端点](score.json)

现有安装版的情景计算可以直接调用。输入 shape、目标芯片和阶段服务率就能复现冻结值。

```python
from operator_model import estimate, load_chip
from operator_model.quant_stream_memory import scenario

shape = [16384, 7168]
chip = load_chip("Ascend950PR_957b")
base = estimate("quant", shape, chip=chip)
cold = scenario(shape, chip, base.latency_us, mixed_bus_efficiency=0.8041000818419384)
print(cold["latency_us"], cold["active_aiv"], cold["plan"]["iterations"])
# 271.7997599745191 56 54
```
