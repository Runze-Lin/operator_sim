## 为什么测这两种大小

分块例在 950DT/PR 上都预测 [512,64,32] 的 MMAD，DT 分 2 波、预测 14,336 条，PR 为 3 波、17,920 条。全形保持权重宽度和 K，通过增加 M 把预测波数拉到 16 / 19，MMAD 数增至 114,688 / 118,272。这个对照可以检查波间进给和末波切分是否真的按模型增长。源文件中 30 个层复用同一几何，因此这两种大小各算一个形状。[逐端资源预测、分核和冻结参数](freeze.json)

可再做两个量纲检查。理论计算时间为 $2MNK/P_{16}$，其中 $P_{16}$ 是 BF16 整卡峰值；假设 X 和 W 各从片外取一次、Y 全部在设备窗内写回，则片外传输时间为 $2(MK+KN+MN)/B$，其中 2 是 BF16 每元素字节数、$B$ 是该芯片配置的带宽。32,768 行对应 950DT 的 69.59 / 118.72 µs 和 950PR 的 79.54 / 339.20 µs（计算 / 片外）。262,144 行的两端片外估计为 948.14 / 2708.98 µs。模型给出的 950PR 全形时间比后一条件估计低 0.74%；仅 X 的 3.5 GiB 满速读就需 2684.35 µs。未来应对照真实 GM/L2 流量与最后的写回，辨别 Y 可见与物理片外写回是否在同一计时窗口。先验模型对 PR 外存利用率接近峰值的判断将在完整实测后检验。

## 采集成本与验收

分块例复用 Kimi-head、三组 decode 完成后的已有串行槽，顺序为 DT、PR；每端限 6 小时、16 GiB 原始文件，开跑前至少有 48 GiB 可用磁盘。官方 `msopprof simulator --dump=false` 保留全部核的指令窗，关闭重复的原始指令转储。一次物理执行同时完成数值与计时检查，运行目录和不合格记录均予保留。全形沿用原冻结预算每端 24 小时、96 GiB。[同槽前序状态](../decode/state.json) · [采集与验收实现](../../../../development/validation/matmul32/pro_large.py)

分块例逐元素核对全部 2,097,152 个输出，同时校验物理 SKU、内存配置、单个 STARS 任务起止和安装版 MatMulV3 ELF。设备耗时从所有活动核最早指令至最后引擎退休，每个活动核须有物理 END，核表与各核时间须吻合；标量 END 后仍在排空的流水按实际退休处理。时间合格后再分别报告 AIC、AIV 和 MMAD 是否符合预报。输入规模、完整性、时间预算任何一项未达要求时保留诊断与成本，相关 CA 或误差栏为 N/A。冻结时系统预测 0.28–3.27 ms，离线采集单独记账。[此前同协议的设备整窗校验](../../../../development/validation/matmul28/drain.py) · [独立分块实验目录](.)
