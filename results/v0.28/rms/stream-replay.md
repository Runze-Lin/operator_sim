**保留当前有序流默认估时。** 当上一调用成功时，`OperatorStream.advance` 记住已用 AIV 的确切覆盖或可证明的下界。它对 RMS 使用相同的占用 H 解释普通已覆盖调用和立即复跑，既不接受输入存储身份，也不保存上一次 RMS 的合同。v0.28 的确切复跑价格在 PR 降了最大误差，却使 WAPE 上升。下面两个旧批次在 PR 也有相同方向。把下一次相同形状一律切换缺少双端净收益。

## 哪种复用证据可以作为输入

已有 v0.28 的 20 个跨两侧实测对中，所有逻辑行块的 x、γ、y、rstd 的 GM 地址和字节数均逐块复核，20 对完全相同。宿主在 batch 循环前只创建一个 ACL 应用流，每次 `aclnnRmsNorm` 后同步，目标任务号相邻且设备窗互不重叠。CA 导出的内部 raw_stream_id 随任务序号递增，该字段不能用于断言两次使用同一个内部硬件队列。实验只验证这个实际调度协议，没有新缓冲区、覆盖后重用或跨流的对应对照。[逐块地址摘要和任务身份](stream-addresses.json)

系统拥有实际张量存储与派发记录时，可以在调用方比较设备、应用流、前一条成功提交的 kernel 合同、dtype、形状和缓冲区身份，再显式走现有专项接口。只有形状相同或只知道 AIV 已覆盖时，直接使用普通流。新配对中 A≤4 的同形首遇和复跑存在不可消除的歧义：即使逐形事后选取最佳点，两态同时 WAPE 的理想下界也达到 DT 37.21%、PR 36.93%。这里的 gamma/向量/写回诊断也适用于解释精度，两种合法的估时在不同域各有误差。

```python
from operator_model import rmsnorm_pipeline

# 已核对上一条成功提交的调用与本次具有相同合同及存储布局
estimate = rmsnorm_pipeline([539, 4000], chip="Ascend950PR_957b", dtype="bf16",
                            resident_aiv=54, immediate_repeat=True, diagnostics=True)
# estimate["us"] = 4.839484；同序 CA 为 4.880 µs
```

两个 UB 块的确切复跑在三批已观测形状中均改善，但每端只有一个 v0.28 独立形属于这个分组。其他单块样本上可能变差，当前证据不足以凭此新建自动路由。各模型既有价格均保留。
