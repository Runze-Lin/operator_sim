# 同样的 shape，RMSNorm 与 MXQuant 的偏差

BF16 输入，调用方只给 shape 和芯片。两套历史归档有四种两端相同的几何。下表列 v0.27 公开入口的原预测和该几何归档 CA 的范围，设备时间单位均为 µs。两种库算子的输出、指令依赖和前序协议各自成立，表内对比只控制了芯片和输入几何。

| 每卡 [token, 通道] | 芯片 | DynamicMXQuant 预测 / CA | RMSNorm 预测 / CA | MXQuant / RMS 活动 AIV |
|---|---|---:|---:|---:|
| [1, 128] | Ascend950DT_9582 | 4.231 / 4.325 | 2.226 / 3.454 | 1 / 1 |
| [1, 256] | Ascend950DT_9582 | 4.231 / 4.493 | 2.239 / 3.637 | 1 / 1 |
| [9, 5120] | Ascend950DT_9582 | 4.980 / 4.867 | 3.241 / 4.161–4.188 | 45 / 9 |
| [36, 5120] | Ascend950DT_9582 | 5.292 / 5.584 | 5.856 / 5.289 | 60 / 36 |
| [1, 128] | Ascend950PR_957b | 3.592 / 3.828 | 2.169 / 3.129 | 1 / 1 |
| [1, 256] | Ascend950PR_957b | 3.592 / 3.859 | 2.183 / 3.155 | 1 / 1 |
| [9, 5120] | Ascend950PR_957b | 4.377 / 5.025 | 3.191 / 3.748 | 45 / 9 |
| [36, 5120] | Ascend950PR_957b | 4.547 / 5.052 | 5.835 / 6.183 | 54 / 36 |

当行数只有 1、宽为 128/256 时，RMSNorm 的无前序点在两端都明显偏低。到 [36,5120]，950PR 的 RMSNorm 比 Quant 更接近 CA。算子名称和 Vector 峰值都不足以解释这个差异。

RMSNorm 归约一整行才能获得 rstd；归一化输出和小体积统计量有两个完成边界。MXQuant 按 32 个元素的微缩放组计算并写量化值与 scale，组之间可以流水推进。二者都可能受 MTE、首次和局部写竞争影响，但参与关键路径的依赖不同。对于大 Kimi Quant，超过 L2 后主要需要解释共享读写和控制器的空数据拍。[Quant 大形](../v0.27/quant-channel-service.md) · [RMSNorm 逐核读与前序](../v0.27/rms/report.md) · [算子身份、源文件与全部观测](vector-matched.json)
