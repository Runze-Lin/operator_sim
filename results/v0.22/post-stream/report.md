# mHC Post 在跨算子调用链中的误差

将同一个公开 `OperatorStream` 依次推进 Pre、Sinkhorn 和 Post，950PR 的 10 个实测形状中，Post 的 WAPE 为 **6.93%**，最大误差 **14.29%**。这 10 次跨族调用的 Post 都选择了“历史未知”，预测值与直接传 shape 一致。若把前一项 Sinkhorn **实测**用过的 AIV 数直接传给 Post，WAPE 反而增至 **24.29%**。链的顺序可以确认，前一个算子用了哪些核也可以观测；这两项证据仍不足以确定 Post 能复用多少热态资源。[逐形状输入、三个 kernel 的计时、核数和对照](replay.json)

| 真实宿主、运行口径 | 不同 shape | 链内 Post WAPE / 最大 | 三段设备窗之和 WAPE / 最大 | 强制继承 Sinkhorn 实测核数，Post WAPE / 最大 |
|---|---:|---:|---:|---:|
| 950DT，msOpProf Simulator 官方全核 trace | 1 | 13.95% / 13.95% | 9.13% / 9.13% | 15.91% / 15.91% |
| 950DT，npusim 三个完整指令数据库 | 23 | 8.67% / 20.75% | 3.25% / 7.75% | 20.71% / 30.50% |
| 950PR，msOpProf Simulator 官方全核 trace | 10 | 6.93% / 14.29% | 5.45% / 12.10% | 24.29% / 30.61% |

所有行均为旧宿主的新回放，以 Post trace 指纹去重。相同 DT 形状在两种仿真器的结果单列。WAPE 等于绝对误差之和除以 CA 时间之和，最大误差按单个 shape 计算。三段时间逐个取全核首条到末条设备指令，串行求和，排除宿主同步和中间正确性检查的时间。第二列 Post 误差用于判断驻留策略；三段之和还包含 Pre 与 Sinkhorn 各自的误差。

## 宿主实际做了什么

安装包的三个调用依次是 ops-transformer 的 `aclnnMhcPre`、`aclnnMhcSinkhorn` 和 `aclnnMhcPost`。C++ 宿主将同一 `aclrtStream` 参数传给三者，各次调用后同步。Pre 生成的 residual 矩阵作为 Sinkhorn 输入，归一化结果和 Pre 的 hin、post 权重都成为 Post 的输入。每条链通过包括 `chain_sinkhorn`、`chain_post` 和 `chain_end_to_end` 在内的九组正确性检查。[实际宿主](../../../smoke/extension_indexer_mhc.cpp) · [官方核记录](../../v0.17/sku/records.json)

例如 950PR 的 BF16 `[T,N,D]=[1,4,128]` 依次运行如下。此形状的 Pre 核数估计仍有明确偏差，三个 stage 不能拿 Post 的核数统一代替。

| 阶段 | 安装包实际 kernel | 预测 / CA µs | 预测 / 实测 AIV |
|---|---|---:|---:|
| Pre | `MhcPre_52e042c374f575edbe357a32523dba2c_2_mix_aic` | 8.378 / 7.638 | 1 / 56 |
| Sinkhorn，20 轮、FP32 | `MhcSinkhorn_8997d9c5c22e82688b98bc25d8daa9cd_0` | 5.869 / 5.193 | 1 / 1 |
| Post | `MhcPost_59130ccee6717ff2c0f15b485e731162_5` | 3.046 / 2.665 | 1 / 1 |

在 950DT 的同形官方运行中，三项实测用 64、1、1 个 AIV，公共 Pre 路线没有返回 AIV 数。DT compact 的指令库提供按序编号的 `entry_kernel_*`、各核起止和数据库指纹。旧收集器一度拒绝宽度 64 和 80 的两个 Pre 入口；原发布器用三个按顺序完成的宿主任务、九项输出和不同的 Pre 内核重新确认。本次重查两个原始日志中的三道任务边界并核对六个 DB 指纹。底层记录中的任务 stream ID 可以变化，运算依赖和先后顺序由宿主同一流参数与同步点确定。[历史重验逻辑](../../../scripts/fusion-v8-report.py) · [compact 发布记录](../../v0.12/evaluation.json)

## 同形 Post 在哪两种调用方式下有直接对照

表中每一行均比较两个真实宿主。官方行核对相同芯片、输入形状、Post 的二进制 SHA-256、kernel 名和实际 AIV 数。compact 行对上了入口名、形状和 AIV 数，二进制身份在数据库中不能单独复核。所有时间均为 µs。

| 芯片与采集方式 | shape | 独立首发，流预测 / CA | 跟在 Pre、Sinkhorn 之后，流预测 / CA |
|---|---|---:|---:|
| DT，官方 | [1,4,128] | 4.721 / 4.752 | 3.044 / 2.672 |
| PR，官方 | [1,4,128] | 4.723 / 4.255 | 3.046 / 2.665 |
| PR，官方 | [1,4,64] | 4.689 / 4.132 | 3.008 / 2.654 |
| PR，官方 | [9,4,1024] | 4.792 / 4.700 | 3.124 / 3.585 |
| DT，compact | [1,4,128] | 4.721 / 4.646 | 3.044 / 2.670 |
| DT，compact | [1,4,64] | 4.688 / 4.588 | 3.007 / 2.739 |

PR 的三个二进制相同的对照中，独立首发 WAPE / 最大为 **8.54% / 13.47%**，接在 Sinkhorn 后为 **13.43% / 14.29%**。例如 `[1,4,128]`，若把 Sinkhorn 的 1 个 AIV 当成可直接复用的 Post AIV，公开预测会变成 **2.248 µs**；实际 **2.665 µs** 位于该热态估计与未知状态估计之间。末核证据还显示，PR 的前两笔操作数读之间的发起间隔从独立运行的 0.395 缩到 0.279 µs，最后一笔读完成到首次向量操作数装载的间隔却从 0.060 增到 0.601 µs。两种不同的延迟发生了反向变化，不能用一个“前序用了几个 AIV”的值代表。[阶段证据](../../post-candidate/issue-response.md)

## 同族连续调用能确定什么

`[3,4,5376]` 还有同一 `vector_v8` 宿主、相同 Post 连续执行两次的双端 CA。回放仅用一条新流顺序执行两次 `advance`，第一次选 `first`，第二次选 `reuse`。

| 芯片 | 首发预测 / CA µs | 第二次预测 / CA µs | 两次 WAPE / 最大 |
|---|---:|---:|---:|
| DT | 4.855 / 5.370 | 2.380 / 2.122 | 10.31% / 12.15% |
| PR | 4.861 / 4.995 | 2.386 / 2.086 | 6.12% / 14.37% |

该对照每端仅一个形状、两个启动序号。它支持在已知的连续同族调用中使用流状态。跨族对照证明调用历史确实影响时间，尚未把各 AIV 的物理通道、数据缓存命中、队列启动状态区分开。旧链也包含宿主的同步和拷回操作，真实 vLLM 请求间的连续排队时序仍需单独验证。[同族真实宿主](../../../smoke/vector_v8.cpp) · [两次 dispatch 的冻结与逐阶段测量](../../post-candidate/paired-result.md)
