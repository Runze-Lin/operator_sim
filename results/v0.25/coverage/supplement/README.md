冻结时，程序核对了 135 份含 FA 记录的本地版本化 JSON 及历史采集目录名，合并出 415 种已登记、测量或推演的几何，七个新输入都未匹配。旧三形的两版预测在所有 SKU 上重算，与原冻结值的绝对差不超过 10⁻¹² µs。[去重明细](novelty.json) · [原三形登记](../fa-freeze.json)

**CA 资格。** 每次使用同一个宿主 ELF 和确定性带正负 BF16 的 Q/K/V。宿主用 double 做 QK、稳定 softmax、PV，对所有 Q×B×H×D 个主输出元素逐项检查，atol=0.002、rtol=0.01。独立核对运行 SKU、物理存储配置、正式算子 ELF、单 kernel、所有核的 END、若有的末尾 END_LABEL、各核窗口及全局起止。设备耗时从第一条设备指令至最后一个核退休。实测核数、MMAD 数、双端快慢与预测的差异均保留。任何不合格回执都附原因，不计算误差。辅助 softmax max/sum 张量不在数值评分对象内。

**运行和恢复。** 一次只开一个 CA，负载 nice 12。先让 v0.24 KDA 补充队列结束，并给更早登记的 Pro 作业启动机会。每次启动前检查一分钟负载小于逻辑核数的 72%、可用内存至少 48 GiB、磁盘至少 80 GiB。含厂商解析的十四端 CA 加总预算 12,720 秒、33,400 MiB，排队时间另计。29 头两端分别最多 20 分钟；32Ki+1 两端分别最多 30 分钟。已有成功或失败回执会跳过；已有采集成本文件可直接续作资格核对；若只有中断的裸文件，队列会保留现场并报告具体 ID。

在仓库根目录可用下列命令恢复和重新计算累计误差。tmux 会话名为 fa-supplement-v025，已有采集进程持有排他锁。运行必须在安装了原 CANN 和对应锁定二进制的主机上。单独重算分数只需精简回执，误差使用登记值。

~~~bash
nice -n 12 python3 development/validation/coverage25/fa_supplement.py run
python3 development/validation/coverage25/fa_supplement.py score
~~~
