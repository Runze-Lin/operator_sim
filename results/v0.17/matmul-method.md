# MatMulV3：末波分块、跨波写回与共享带宽

输入为单卡 BF16 连续 ND 的 `[M,N,K]`。输出块不是全芯片同时开始/结束的屏障。一个核可以在上一个输出块尚未写完时开始读下一个；最后若只剩几个父块，库还可沿输出行列把它们再分给空闲核。仍按目标配置计算 tile、峰值、缓冲和带宽；无 SKU 分支或总时延拟合。首读、MMAD、L0、写回的时间参数仍来自 [17 份 DT 指令 trace](../v0.16/matmul-dt-provenance.json)。**跨波调度与可见写回假设**利用了旧 PR 误差的事后诊断，不是完全未接触 PR 的架构研究。

**1. 最后一波实际发什么。** `A,B` 是主输出块的 M/N 尺寸，`J=ceil(M/A)ceil(N/B)` 个父块，`C` 是 AIC 数。仅当已有整波且末尾 `t=J mod C>0` 时尝试拆分。分割计数从 `sₘ=sₙ=1` 起，若 `(sₘ+1)sₙt≤C` 则增加 M 切数；有余核且未拆的 N 子块大于 128 B，再尝试增加 N 切数。运行时将 host 的切数按真实边界调整，实块 `a×b` 的片尺寸按 `ceil(a/sₘ),ceil(b/sₙ)` 裁边，不按 16 对齐当作有效几何。迭代次序来自本地 ops-nn 的 [CalcTailBasicBlock](https://gitcode.com/cann/ops-nn/blob/602e4ad985da00aad28c16432841e9c5069e10de/matmul/mat_mul_v3/op_host/op_tiling/arch35/matmul_v3_asw_tiling.cpp) 和 [BlockSchedulerAswtBuiltIn](https://gitcode.com/cann/ops-nn/blob/602e4ad985da00aad28c16432841e9c5069e10de/matmul/mat_mul_v3/op_kernel/arch35/block_scheduler_aswt.h)（commit `602e4ad985da`）：四行窗口、交替方向。每个输出片独自累加完整 K，故 `MMAD数=有效输出片数×ceil(K/k₀)`，其中 `k₀` 为 L0 计算片深。只枚举最后一波；此前所有波直接由行、列余数得到几何直方图。

**2. 给每条路径计工作。** 以 `H(a,b)` 表示给定波的子块尺寸计数。深度 `d` 的输入 L2 重复流量为 `X=2d ΣH(a,b)(a+b)` B；输出有效流量为 `Y=2ΣH(a,b)ab` B。多组前置整波用所有前置作业的准确汇总字节除以组数；最重本地描述符仍按最大实块计算，不将平均元素/核当尾部关键路径。L2 可容纳输入页时假定 HBM 对输入一次冷读、否则按重复读，这是场景而非命中率观测。

`S` 是目标 L2 容量，`Xcold` 是一页唯一输入字节，`Yo=2MN` 是整算子输出。指定可留脏比例 `ρ=matmul_output_retained_fraction∈[0,1]`，指本算子结束时仍可能驻留的输出。可留字节 `D=ρ min(Yo,max(0,S−Xcold))`；本窗内暴露的外存写为 `Yh=Yo−D`，最终仍要处理全部输出。默认 `ρ=1` 描述 write-back 缓存场景，**容量不是命中证明**；若认为结束前必须落入外存，可设 `ρ=0`。例如 PR `[1536,2048,16]` 默认 4.969 µs，直写假设 8.101 µs。在旧 PR trace 中，6,291,456 个有效输出字节除以整个 FIX 描述符窗口为 2240 GB/s，高于该 SKU 的标称片外 1400 GB/s；这说明“描述符全部时长＝板上 HBM 全量写入时间”解释不成立，并不证明实际写回了哪一级。

**3. 吞吐与跨波发起。** 全芯片 HBM/L2 名义带宽分别为 `Bh,Bl`，可用上限 `ηh Bh, ηl Bl`；`matmul_hbm_efficiency,matmul_l2_efficiency∈(0,1]`，默认 1，表示不假定一个未测的折扣系数。下文周期制带宽均用 bytes/cycle（十进制 GB/s 除以 GHz），每核 MTE 带宽单独定价。给定一波，写 payload 服务周期为 `Wᵢ=max(最大子块字节/每核写带宽, Y/(ηl Bl), Y·Yh/Yo/(ηh Bh))`，首次写完成周期 `W=Wᵢ+固定写延迟`。读同理取每核描述符、波内 L2 和暴露 HBM 三个上界中最慢者；首完成加固定延迟，发起间隔只收端口/队列需求。少核小传输既有首延迟，又只能使用少数端口；不会按整芯片峰值直接换算所有阶段。

每个波的读首完成 `R`、搬至 L0 的提前量 `L`、页间时间 `P`、末页计算 `G` 与写完成 `W` 单独计价（见[页内规则](../v0.16/matmul-method.md)）。同质整波的读发起间隔 `Iᵣ=max(读取服务,(R+L)/2)`，分母 2 对应两个预取槽；Cube 的连续发起间隔 `I꜀` 取 K 分片/页的计算发起服务与 `Iᵣ` 中较大者，写服务间隔 `I𝑤=max(I꜀,Wᵢ)`。相邻波的计算开始为 `max(本波读就绪,上一波计算开始+上波计算服务)`；本波写开始为 `max(本波计算完成,上一波写开始+上波写payload服务)`。末波按自己的几何和端口服务重算；完成时间是前置波和末波排空时刻的最大值。最后以合计 L2 或 HBM 流量/相应可用带宽作共享链路下界，**只补超过流水时长的差额**。此前完整一致波用发起间隔闭式累计；不逐条重放指令。尚未建模每个地址的命中或队列争用、所有前置波的具体核序、架构变化后的新 kernel。

`shared_traffic` 公开两条路径的端到端有效 GB/s 和 `流量/(设备预测时长×该路径名义峰值)`。这是含启动/低占用的**预测 payload 比率**而非板上实测或配置折扣 η。例如 PR `[2,32,32]` 的 L2 比率约 0.016%，`[1536,2048,16]` 约 31.1%；同一芯片也区别显著。两者分别预测 1 核与 28 核。前者用绝大部分时间发起，后者的数据量足以使共享带宽和重叠影响总耗时。
