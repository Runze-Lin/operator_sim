# 双端留出的计时口径

估算端固定 BF16、两端都用 resource、不提供 resident_aiv。20 个主输入先在上一版排除集与 v0.18 归档中去重。按行数预分小（<32）、分核边界（32–128）和大（>128）三组。10 对/算子用于独立比较；RMSNorm 老版公开边界为 512 行，因此 2048 行另外统计。Quant 的 2048 行在历史场景枚举中出现过，同样单列。实测两端分别为 Ascend950DT_9582 和 Ascend950PR_957b，970DT 只根据情景配置计算。

冻结信息见 [freeze.json](freeze.json)。其中收录两份预测的摘要、包内资源、芯片 JSON、运行器及采集脚本。最初的登记在首次 CA 前修订了一处补充结果的拼接代码，保留了初版记录。耗时与模型摘要相同。若随后新增分支改变了公共入口，可从提交 e6eb2c7369904f1332356a67829c26bad57703fe 取回本轮主路线的源文件。旧版由独立安装的 v0.18 wheel 生成，数据、模型代码和 Git 提交相互独立保存。

两端使用 CANN 9.2.1 msopprof 同一主程序，不导出冗余的原始指令文本。完整 trace 仍包含每个活动核的指令和窗口。检查实际 SKU、内存模型、ACLNN 形参、host 和 kernel 身份。RMSNorm 核对全部 y 与 rstd；Quant 对全部量化值和 scale 做字节级检查。设备耗时等于全核最后指令结束减最早指令开始。host、离线仿真、导出与在线查询分别计时。

在受限环境中 profiler 的本机 socket 被拒绝，初始化的 10 个启动或中断记录单列。受限环境的数值结果没有用作设备时间。正常环境的物理尝试及超限原因也予以保留。导出收尾超限时，可检查内部已经落盘的完整全核 JSON。须同时具备相同 SKU/算子的正式对照、每核的第一与最后指令、完整数值 golden、完整 kernel 身份与哈希、与厂商逐核时长表吻合（绝对误差≤0.011 µs）。满足条件只恢复已有时间窗，不增加物理启动数。缺任何条件即为缺测。原始预测保持冻结。
